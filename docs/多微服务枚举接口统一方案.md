## 1. 背景与问题

### 1.1 现状

框架通过 `/app/enum` 接口暴露每个微服务的枚举对象，由 `carlos-spring-boot-starter-web` 模块的 `ApplicationController` 提供：

| 接口     | 方法  | 路径           | 描述                 |
|--------|-----|--------------|--------------------|
| 所有枚举字典 | GET | `/app/enums` | 获取全部枚举字典列表         |
| 单个枚举详情 | GET | `/app/enum`  | 参数 `name`，获取指定枚举详情 |

### 1.2 问题

各微服务的 Controller 前缀不一致：

| 微服务            | Controller 前缀 | 枚举接口路径            |
|----------------|---------------|-------------------|
| carlos-system  | `/sys/xxx`    | `/sys/app/enum`   |
| carlos-org     | `/org/xxx`    | `/org/app/enum`   |
| carlos-auth    | `/auth/xxx`   | `/auth/app/enum`  |
| carlos-message | `/msg/xxx`    | `/msg/app/enum`   |
| carlos-audit   | `/audit/xxx`  | `/audit/app/enum` |

**问题核心**：前端无法统一处理枚举的获取和使用，需要知道每个枚举属于哪个微服务。

---

## 2. 方案概述

| 部署模式      | 策略                | 前端调用方式                                  |
|-----------|-------------------|-----------------------------------------|
| **单体聚合**  | boot 模块统一扫描所有枚举包  | `/app/enums`、`/app/enum`                |
| **微服务**   | Gateway 并发聚合各服务枚举 | `/app/enums`、`/app/enum`（Gateway 统一入口）  |
| **微服务直连** | 前端维护枚举→服务映射表      | 自动路由到 `/sys/app/enum`、`/org/app/enum` 等 |

**推荐路径**：当前使用**单体聚合**（零代码改动即可），未来切微服务时启用**Gateway 聚合**。

---

## 3. 方案一：单体模式 - 统一扫描（推荐当前使用）

所有枚举集中在一个 boot 模块管理，配置扫描所有业务模块的枚举包。

### 3.1 后端配置

在 boot 模块（如 `carlos-system-boot`）的 `application.yml` 中配置：

```yaml
carlos:
  boot:
    enums:
      enabled: true
      scan-package:
        # system 模块
        - com.carlos.system.enums
        - com.carlos.system.dict.pojo.enums
        # org 模块
        - com.carlos.org.pojo.enums
        # auth 模块
        - com.carlos.auth.app.pojo.enums
        - com.carlos.auth.audit.pojo.enums
        # message 模块
        - com.carlos.message.pojo.enums
        # audit 模块
        - com.carlos.audit.pojo.enums
        - com.carlos.audit.api.pojo.enums
```

### 3.2 效果

启动后访问 `GET /app/enums`，一次性返回所有模块的枚举字典。前端代码**完全不用改**。

### 3.3 优缺点

| 优点           | 缺点                 |
|--------------|--------------------|
| 零代码改动，配置即生效  | 单体模式下所有枚举在一个 JVM 中 |
| 前端无需感知服务分布   | 枚举包路径需手动维护         |
| 性能最优（本地内存缓存） | 微服务拆分后需切换方案        |

## 4. 方案二：微服务模式 - Gateway 聚合（推荐未来使用）

在 `carlos-gateway` 增加枚举聚合接口，内部并发调用各服务，前端无感知。

### 4.1 后端实现

新建 `carlos-gateway/src/main/java/com/carlos/gateway/enums/EnumAggregationController.java`：

```java
package com.carlos.gateway.enums;

import com.carlos.core.enums.EnumInfo;
import com.carlos.core.response.Result;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.core.ParameterizedTypeReference;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.reactive.function.client.WebClient;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * Gateway 枚举聚合控制器
 * 内部并发调用所有业务服务的 /app/enums 接口，合并后统一返回
 */
@Slf4j
@RestController
@RequestMapping("/app")
public class EnumAggregationController {

    @Autowired
    private WebClient.Builder webClientBuilder;

    /**
     * 需要聚合枚举的服务列表，按实际情况配置
     */
    @Value("${carlos.gateway.enum.services:carlos-system,carlos-org,carlos-auth,carlos-message,carlos-audit}")
    private List<String> enumServices;

    /**
     * 聚合所有服务的枚举字典
     * GET /app/enums
     */
    @GetMapping("/enums")
    public Mono<Result<Map<String, List<EnumInfo>>>> allEnums() {
        List<Mono<Map<String, List<EnumInfo>>>> calls = enumServices.stream()
            .map(this::fetchServiceEnums)
            .toList();

        return Flux.merge(calls)
            .reduce(new HashMap<>(), (acc, map) -> {
                acc.putAll(map);
                return acc;
            })
            .map(Result::success);
    }

    /**
     * 按名称查询枚举（并发查询所有服务，返回第一个命中的结果）
     * GET /app/enum?name=ConfigValueType
     */
    @GetMapping("/enum")
    public Mono<Result<List<EnumInfo>>> enumInfo(@RequestParam String name) {
        List<Mono<List<EnumInfo>>> calls = enumServices.stream()
            .map(service -> fetchServiceEnum(service, name))
            .toList();

        return Flux.merge(calls)
            .filter(list -> list != null && !list.isEmpty())
            .next() // 取第一个非空结果
            .map(Result::success)
            .defaultIfEmpty(Result.error("枚举不存在: " + name));
    }

    private Mono<Map<String, List<EnumInfo>>> fetchServiceEnums(String serviceId) {
        return webClientBuilder.build()
            .get()
            .uri("lb://" + serviceId + "/app/enums")
            .retrieve()
            .bodyToMono(new ParameterizedTypeReference<Result<Map<String, List<EnumInfo>>>>() {})
            .mapNotNull(Result::getData)
            .onErrorResume(e -> {
                log.warn("获取服务[{}]枚举字典失败: {}", serviceId, e.getMessage());
                return Mono.just(Map.of());
            });
    }

    private Mono<List<EnumInfo>> fetchServiceEnum(String serviceId, String name) {
        return webClientBuilder.build()
            .get()
            .uri(uriBuilder -> uriBuilder
                .scheme("lb")
                .host(serviceId)
                .path("/app/enum")
                .queryParam("name", name)
                .build())
            .retrieve()
            .bodyToMono(new ParameterizedTypeReference<Result<List<EnumInfo>>>() {})
            .mapNotNull(Result::getData)
            .onErrorResume(e -> {
                log.warn("获取服务[{}]枚举[{}]失败: {}", serviceId, name, e.getMessage());
                return Mono.empty();
            });
    }
}
```

### 4.4 优缺点

| 优点                  | 缺点                       |
|---------------------|--------------------------|
| 前端完全无感知，接口统一        | 增加 Gateway 一层网络开销        |
| 微服务独立部署，枚举自然隔离      | 需引入 WebClient/Reactor 依赖 |
| 服务故障自动降级（不影响其他服务枚举） | 枚举名称全局唯一约束               |

## 5. 前端统一封装（两种模式通用）

无论后端是单体扫描还是 Gateway 聚合，前端调用方式完全一致。

### 5.1 服务层

新建 `carlos-ui/src/service/api/app.ts`：

```typescript
import { request } from '../request';

export interface EnumItem {
  code: string | number;
  desc: string;
  name: string;
}

/** 获取所有枚举字典 */
export function fetchGetAllEnums() {
  return request<Record<string, EnumItem[]>>({
    url: '/app/enums',
    method: 'get'
  });
}

/** 获取单个枚举详情 */
export function fetchGetEnumInfo(name: string) {
  return request<EnumItem[]>({
    url: '/app/enum',
    method: 'get',
    params: { name }
  });
}
```

### 5.2 枚举状态管理

新建 `carlos-ui/src/store/modules/enum/index.ts`：

```typescript
import { defineStore } from 'pinia';
import { fetchGetAllEnums, fetchGetEnumInfo, type EnumItem } from '@/service/api/app';

export const useEnumStore = defineStore('enum-store', {
  state: () => ({
    /** 枚举缓存: { 枚举名: 枚举项列表 } */
    cache: {} as Record<string, EnumItem[]>,
    /** 是否已全量加载 */
    loaded: false
  }),

  getters: {
    /** 获取枚举项列表 */
    getEnumItems: (state) => (name: string): EnumItem[] => {
      return state.cache[name] || [];
    },

    /** 转换为 Select/Option 组件的 options 格式 */
    getEnumOptions: (state) => (name: string): { value: string; label: string }[] => {
      const items = state.cache[name] || [];
      return items.map(item => ({
        value: String(item.code),
        label: item.desc
      }));
    },

    /** 根据 code 获取描述文本 */
    getEnumDesc: (state) => (name: string, code: string | number): string => {
      const items = state.cache[name] || [];
      const found = items.find(item => String(item.code) === String(code));
      return found?.desc || String(code);
    },

    /** 根据 code 获取 name（枚举常量名） */
    getEnumName: (state) => (name: string, code: string | number): string => {
      const items = state.cache[name] || [];
      const found = items.find(item => String(item.code) === String(code));
      return found?.name || String(code);
    }
  },

  actions: {
    /** 按需加载单个枚举 */
    async loadEnum(name: string): Promise<EnumItem[]> {
      if (this.cache[name]) return this.cache[name];

      const { data, error } = await fetchGetEnumInfo(name);
      if (!error && data) {
        this.cache[name] = data;
      }
      return this.cache[name] || [];
    },

    /** 批量加载枚举 */
    async loadEnums(names: string[]): Promise<void> {
      await Promise.all(names.map(name => this.loadEnum(name)));
    },

    /** 全量加载所有枚举（登录后调用一次） */
    async loadAllEnums(): Promise<void> {
      if (this.loaded) return;

      const { data, error } = await fetchGetAllEnums();
      if (!error && data) {
        this.cache = { ...this.cache, ...data };
        this.loaded = true;
      }
    },

    /** 清空缓存 */
    clearCache() {
      this.cache = {};
      this.loaded = false;
    }
  }
});
```

### 5.3 页面使用示例

```vue
<script setup lang="ts">
import { useEnumStore } from '@/store/modules/enum';

const enumStore = useEnumStore();

// 方式1：登录后全量加载（推荐枚举数量不多时）
onMounted(async () => {
  await enumStore.loadAllEnums();
});

// 方式2：页面按需加载（推荐枚举数量多时）
onMounted(async () => {
  await enumStore.loadEnum('ConfigValueType');
  await enumStore.loadEnum('OrgUserStateEnum');
});

// 表格列渲染
const columns = [
  {
    key: 'valueType',
    title: '值类型',
    customRender: ({ record }) => enumStore.getEnumDesc('ConfigValueType', record.valueType)
  },
  {
    key: 'userState',
    title: '用户状态',
    customRender: ({ record }) => {
      const desc = enumStore.getEnumDesc('OrgUserStateEnum', record.state);
      const colorMap: Record<string, string> = { '1': 'success', '2': 'error' };
      return h(Tag, { color: colorMap[String(record.state)] }, () => desc);
    }
  }
];

// 表单下拉选择
const valueTypeOptions = computed(() => enumStore.getEnumOptions('ConfigValueType'));
</script>

<template>
  <ASelect v-model:value="formModel.valueType" :options="valueTypeOptions" placeholder="请选择值类型" />
</template>
```

## 6. 方案三：微服务直连 - 前端服务映射（兜底方案）

如果暂时无法做 Gateway 聚合，前端直接调用各服务，需维护映射表。

### 6.1 多服务请求实例配置

`carlos-ui/.env.development`：

```bash
# 各微服务 baseURL 配置（JSON5 格式）
VITE_OTHER_SERVICE_BASE_URL='{
  sys: "http://localhost:8081",
  org: "http://localhost:8082",
  auth: "http://localhost:8083"
}'
```

### 6.2 枚举服务映射

新建 `carlos-ui/src/constants/enum-service.ts`：

```typescript

 * 枚举名 -> 服务标识映射
 * 新增枚举时必须同步维护此映射
 */

  // system 模块
  ConfigValueType: 'sys',
  DictTypeEnum: 'sys',
  MenuType: 'sys',
  UserMessageType: 'sys',
  // org 模块
  OrgUserGenderEnum: 'org',
  OrgUserStateEnum: 'org',
  OrgRoleTypeEnum: 'org',
  OrgRoleStateEnum: 'org',
  OrgPermissionTypeEnum: 'org',
  OrgPermissionStateEnum: 'org',
  OrgDataScopeEnum: 'org',
  OrgDepartmentStateEnum: 'org',
  // auth 模块
  ClientStateEnum: 'auth',
  AlertType: 'auth',
  // message 模块
  MessageReceiverStatusEnum: 'message',
  // audit 模块
  AuditLogStateEnum: 'audit',
  AuditLogAuthTypeEnum: 'audit',
  AuditLogCategoryEnum: 'audit',
  AuditLogPrincipalTypeEnum: 'audit',
  AuditLogChangeTypeEnum: 'audit',
  AuditLogBizChannelEnum: 'audit',
  AuditLogAttachmentTypeEnum: 'audit',
  AuditLogAuthProviderEnum: 'audit',
};

/** 根据枚举名获取服务标识，返回 null 表示走默认 baseURL */
export function getEnumService(name: string): string | null {
  return ENUM_SERVICE_MAP[name] || null;
}
```

### 6.3 多实例枚举请求

新建 `carlos-ui/src/service/api/enum-multi.ts`：

```typescript
import { request, createFlatRequest } from '../request';

// 创建各服务的请求实例（复用原有认证逻辑）
const sysRequest = createFlatRequest({ baseURL: '/proxy-sys' }, { /* ... */ });
const orgRequest = createFlatRequest({ baseURL: '/proxy-org' }, { /* ... */ });
const authRequest = createFlatRequest({ baseURL: '/proxy-auth' }, { /* ... */ });

const serviceRequestMap: Record<string, typeof request> = {
  sys: sysRequest,
  org: orgRequest,
  auth: authRequest,
  message: request, // 走默认
  audit: request,
};

import { getEnumService } from '@/constants/enum-service';
import type { EnumItem } from './app';

export function fetchGetEnumInfoFromService(name: string) {
  const service = getEnumService(name);
  const req = service ? serviceRequestMap[service] : request;

  return req<EnumItem[]>({
    url: '/app/enum',
    method: 'get',
    params: { name }
  });
}
```

> **注意**：此方案需要同步维护 `ENUM_SERVICE_MAP`，新增枚举时容易遗漏，仅作为 Gateway 聚合完成前的过渡。

## 7. 长期优化：增强 @AppEnum 注解

在 `@AppEnum` 中增加 `module` 属性，由后端声明所属模块，彻底消除前端映射维护。

### 7.1 注解扩展

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface AppEnum {
    String code();
    /** 所属服务模块，用于 Gateway 路由和前端自动定位 */
    String module() default "";
}
```

使用示例：

```java
@AppEnum(code = "OrgUserGender", module = "org")
public enum OrgUserGenderEnum implements BaseEnum<Integer> {
    MALE(1, "男"), FEMALE(2, "女"), UNKNOWN(0, "保密");
    // ...
}
```

### 7.2 效果

- Gateway 聚合时可按 `module` 精确路由到目标服务
- 前端可自动生成 `枚举名 -> module` 映射，无需手动维护
- 未来可扩展为后端启动时上报枚举清单到注册中心

## 8. 实施建议

| 阶段     | 行动                                         | 改动范围              |
|--------|--------------------------------------------|-------------------|
| **立即** | 单体模式：在 boot 模块配置全量枚举扫描包                    | `application.yml` |
| **近期** | 前端：建立 `useEnumStore` 统一管理枚举缓存              | 新增 2 个文件          |
| **中期** | Gateway：增加 `EnumAggregationController` 聚合层 | 新增 1 个文件          |
| **远期** | 增强 `@AppEnum` 增加 `module` 属性，支持自动路由        | 注解 + EnumService  |

### 当前推荐做法

1. 在 `carlos-system-boot` 的 `application.yml` 中配置所有枚举扫描包（方案一）
2. 前端新建 `useEnumStore` 统一管理枚举缓存（5.2 节）
3. 页面按需使用 `enumStore.loadEnum()` 和 `enumStore.getEnumOptions()`
