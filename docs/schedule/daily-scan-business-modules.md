### 3. 扫描维度与检查清单

> **业务模块评估原则**
>
：以资深平台架构师视角审视业务模块全生命周期质量。对每一个业务模块，首先评估其文档资产是否完整；其次对照模块定位核查需求覆盖度与设计的合理性；然后以本项目编码规范（CLAUDE.md /

#### 3.2 需求覆盖度与合理性评估（最高优先级）

**遗漏需求扫描**

- [ ] **边界需求缺失**：模块是否处理了边界场景？（如 org 部门树的循环引用检测、message 消息发送失败重试、auth 并发登录控制）
- [ ] **异常流程缺失**：除正常流程外，异常流程是否完整？（如部分成功/部分失败的批量操作回滚策略、第三方服务超时后的降级策略）
- [ ] **权限需求缺失**：各业务操作是否都考虑了权限控制？（数据权限、功能权限、字段级权限）
- [ ] **审计需求缺失**：关键业务操作（增删改）是否都有审计日志需求且已接入 `carlos-audit`？
- [ ] **合规需求缺失**：是否满足数据安全合规要求？（敏感数据脱敏、操作留痕、数据保留期限）

**设计合理性扫描**

- [ ] **分层架构合理性**：Controller/Service/Manager/Mapper 分层是否清晰？Service 是否包含过多业务逻辑导致臃肿？
- [ ] **领域模型设计**：Entity 是否与数据库表一一对应？DTO/VO/AO 的分层是否合理？是否存在跨层传输的裸 Map/JSONObject？
- [ ] **Feign 接口设计**：`-api` 模块的接口定义是否满足"最小暴露原则"？返回值是否使用了 AO 而非 VO/Entity？
- [ ] **缓存设计**：缓存策略是否与业务场景匹配？（如 org 部门树是否适合全量缓存、system 字典是否适合本地缓存+Redis 二级缓存）
- [ ] **事务设计**：跨服务调用是否滥用本地事务？是否需要分布式事务（Seata）但未使用？
- [ ] **异步设计**：耗时操作（如批量导入、消息发送）是否异步化？异步任务是否有幂等保障？

#### 3.3 代码规范落实检查（高优先级）

> 以 `.claude/skills/carlos-framework-standard/SKILL.md` 和 `CLAUDE.md` 为强制规范依据，逐条扫描代码落实情况。任何违反强制规范的行为必须标记为
> P1 及以上。

**强制规范（违反即拒绝）**

- [ ] **数据查询规范**：是否使用 MyBatis-Plus + mybatis-plus-join 在 Manager 层查询？是否存在手写 SQL（XML 中直接写
  SELECT *）？
- [ ] **Redis 缓存规范**：Service 层是否直接操作 Redis？缓存是否统一封装在 Manager 层？
- [ ] **异常处理规范**：是否使用框架定义异常类（ServiceException 等）？严禁使用裸 RuntimeException、空 catch 块。
- [ ] **Lombok 规范**：是否使用注解生成 getter/setter/equals/hashCode？严禁手写 get/set 方法。
- [ ] **属性注入规范**：是否使用 `@ConfigurationProperties` 进行属性注入？严禁使用 `@Value`。
- [ ] **Service 返回值规范**：Service 层是否返回 DTO 或 Entity？严禁返回 VO。
- [ ] **枚举规范**：枚举是否实现 BaseEnum 接口？是否使用 `@AppEnum` 注解标记？
- [ ] **不可变性规范**：方法内部是否修改传入参数（Mutation）？是否遵循"创建新对象，不修改原对象"原则？

**命名与格式规范**

- [ ] **命名规范**：类名、方法名、变量名是否符合驼峰/帕斯卡规范？常量是否全大写下划线分隔？
- [ ] **包结构规范**：包命名是否符合 `com.carlos.{service}`？领域模型包是否按 param/dto/vo/ao/entity/enums/excel 分层？
- [ ] **代码格式**：左大括号前是否换行？`if/for/while` 与括号间是否有空格？缩进是否为 4 个空格？单行是否不超过 120 字符？
- [ ] **注释规范**：类和方法是否有必要注释？注释是否为双斜线 + 单个空格？复杂逻辑是否有说明？

**分层与依赖规范**

- [ ] **模块依赖合规**：`-api` 是否不依赖 `-bus`？`-cloud` 是否只依赖 `-api`？`-boot` 是否正确聚合？
- [ ] **Convert 规范**：对象转换是否使用 MapStruct？是否存在手动 Bean 拷贝（`BeanUtils.copyProperties` 泛滥）？
- [ ] **Mapper 引用规范**：Service 层是否通过 Manager 间接操作数据？是否存在 Service 直接引用 Mapper？

#### 3.4 性能风险评估（高优先级）

> 从业务场景出发，评估代码在实际运行中可能出现的性能瓶颈。

**数据库性能**

- [ ] **N+1 查询**：是否存在循环内查询数据库？（如 org 部门树逐节点查询、message 批量发送逐条查询模板）
- [ ] **大表查询**：是否存在无分页的全表查询？（如 audit 审计日志查询、system 操作日志查询）
- [ ] **索引缺失**：Mapper XML 或 MyBatis-Plus 查询条件中的字段，对应的数据库表是否有合适索引？
- [ ] **慢 SQL**：复杂 Join 查询、子查询是否可优化？是否使用了 `EXPLAIN` 分析执行计划？
- [ ] **批量操作**：批量插入/更新是否使用 MyBatis-Plus 批量 API？是否存在逐条 insert 的循环？

**缓存性能**

- [ ] **缓存穿透/击穿/雪崩**：热点数据是否有缓存保护？缓存失效策略是否合理？
- [ ] **Redis 大 Key**：缓存的集合/列表数据是否可能无限增长？（如 audit 未归档的日志列表、message 未消费的消息队列）
- [ ] **缓存一致性**：数据更新后缓存是否及时失效或更新？是否存在脏读窗口？

**服务调用性能**

- [ ] **循环 RPC**：Service 层是否存在循环内调用其他服务 Feign 接口？
- [ ] **同步阻塞**：耗时操作（如第三方短信发送、文件上传）是否在主线程同步执行？
- [ ] **线程池配置**：异步任务使用的线程池参数（核心线程数、队列大小、拒绝策略）是否合理？

**算法与数据结构**

- [ ] **树形递归**：org 部门树、system 菜单树的递归查询是否深度可控？是否存在栈溢出风险？
- [ ] **遍历查找**：List.contains() / List.indexOf() 是否在热点路径频繁调用？是否应换为 Set/Map？
- [ ] **字符串拼接**：循环内字符串拼接是否使用 StringBuilder？
- [ ] **大对象**：是否存在一次性加载大量数据到内存？（如 Excel 导出全量数据、报表查询）

#### 3.5 安全风险评估（最高优先级）

> 业务模块的安全风险直接影响生产系统，必须以最高优先级对待。

**认证授权安全**
- [ ] 是否存在 MD5/SHA1 等弱密码编码器（重点检查 `carlos-auth-service`）
- [ ] OAuth2 Token 是否设置合理过期时间？Refresh Token 轮换是否实现？
- [ ] 登录接口是否实现防暴力破解（限流、账户锁定、验证码）
- [ ] 密码是否安全存储（BCrypt/Argon2，禁止明文或弱哈希）
- [ ] JWT Token 是否包含敏感信息？签名密钥长度是否足够？密钥是否轮换？
- [ ] 网关层 OAuth2 过滤器是否正确校验 Token？是否存在匿名可访问的敏感路径？

**数据安全**

- [ ] **越权访问**：跨服务调用是否传递用户上下文？是否存在水平越权（A 用户访问 B 用户数据）？
- [ ] **数据脱敏**：组织架构导出、用户详情查询中，手机号/身份证/邮箱是否脱敏？
- [ ] **SQL 注入**：是否使用 `${}` 拼接 SQL？动态表名/列名是否有白名单校验？
- [ ] **敏感配置**：密码、密钥、AK/SK 是否硬编码或明文存储在配置文件？

**业务安全**

- [ ] **防重放**：消息发送、短信下发、支付下单等是否实现防重放机制？
- [ ] **防刷限流**：登录、验证码、消息发送是否有频率限制？
- [ ] **违禁词过滤**：消息内容、评论、公告等是否有过滤机制？
- [ ] **文件安全**：文件上传是否限制类型和大小？是否防范路径遍历和文件名注入？

**审计与合规**

- [ ] 审计日志是否防篡改？日志中是否包含密码/Token 等敏感字段明文？
- [ ] **License 安全**：生产环境是否误包含 `carlos-spring-boot-starter-license-generate`
- [ ] 反序列化安全风险：是否校验类白名单？是否存在不安全的 `ObjectInputStream` 使用？

### 4. 深度代码分析要求

对每个发现的问题，必须提供以下信息：

1. **问题定位**：文件路径 + 行号范围（精确到方法或代码块）
2. **相关代码**：完整的代码片段（不少于 5 行上下文）
3. **详细分析**：
    - 问题类型（设计缺陷 / 功能缺失 / 可优化 / 安全漏洞 / 技术债务）

## 扫描规范与约束

### 代码片段规范

- 引用的代码必须**包含完整的方法签名或类定义上下文**
- 必须标注**精确的文件路径和行号范围**
- 代码片段使用 ```java 语法高亮
- 若涉及多文件关联，需分别列出

### 问题分级标准

| 级别              | 定义                   | 响应时效     | 示例                                                |
|-----------------|----------------------|----------|---------------------------------------------------|
| **P0-Critical** | 会导致系统故障、数据丢失、安全漏洞的问题 | 24 小时内修复 | SQL 注入、内存泄漏、硬编码密钥、认证绕过、越权访问、生产含 license-generate  |
| **P1-High**     | 影响核心功能、性能严重下降、违反强制规范 | 本周内修复    | Service 直接调 Mapper、缓存雪崩风险、Feign 无降级、核心需求遗漏、N+1 查询 |
| **P2-Medium**   | 影响代码质量、可维护性、存在潜在风险   | 本月内修复    | 魔法值硬编码、日志占位符缺失、重复代码、设计文档缺失、不合理的缓存策略               |
| **P3-Low**      | 轻微优化建议、风格问题、文档缺失     | 排期优化     | JavaDoc 缺失、变量命名不规范、import 未优化、README 不完整、测试用例未文档化 |

### 分析深度要求

- **每个 P0/P1 问题**必须提供：代码片段（如适用）+ 详细分析 + 完整解决方案
- **每个 P2 问题**必须提供：代码片段（如适用）+ 分析 + 修复建议
- **每个 P3 问题**至少提供：问题描述 + 优化建议
- **文档类问题**：需指明缺失/不合规文档的具体路径和应有的内容结构，提供文档模板参考
- **需求类问题**：需说明遗漏的需求场景及建议补充的功能点
- 单个模块发现超过 5 个问题，需单独输出子章节

### 特殊场景处理

- **无新 Commit**: 仍需基于当前代码全量扫描，报告标注 "今日无代码变更，基于最新 Commit xxx 扫描"
- **新增业务模块**: 优先深度扫描新增模块，标记为 "新增业务模块重点审查"
- **大规模重构**: 若发现某模块正在被大规模重构，可标注 "该模块处于重构期，部分问题可能已被识别"
