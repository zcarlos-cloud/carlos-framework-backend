## 1. 引言

### 1.1 背景

当前框架各微服务（carlos-auth、carlos-system、carlos-org、carlos-audit 等）在生产环境中依赖多种中间件（Redis、关系数据库、ClickHouse、MongoDB 等），且**一个应用往往同时连接多个 Redis 实例和多个数据库**（框架已通过 dynamic-datasource 支持多数据源，但 Redis 仅支持单实例配置）。现状问题：

1. 监控能力分散：Actuator 端点各服务独立暴露、仅网关接了 Prometheus，无统一查看入口；
2. 中间件无管理界面：排查 Redis key、慢查询、大 key、数据库慢 SQL、连接池状态等问题，需要登录服务器用命令行操作，效率低且有安全风险；
3. 无告警机制：中间件故障（内存打满、连接池耗尽、主从切换）只能靠人肉发现；
4. 运维操作无审计：直连中间件改数据无记录、无权限控制。

### 1.2 目标

在系统管理域新增「系统监控」菜单，建设统一的**监控中心**，实现：

- **看得见**：一个应用下所有中间件实例（多个 Redis、多个数据库）与微服务实例的运行状态、核心指标集中可视；
- **管得了**：Redis key 与数据库表数据的在线查询与受控管理（浏览/编辑/删除），替代命令行直连；
- **报得出**：指标阈值告警，对接 carlos-message 多渠道通知；
- **可追溯**：所有数据管理类操作留痕，对接 carlos-audit。

### 1.3 范围

**纳入范围（本期）**：

| 域 | 内容 |
|----|------|
| 监控对象管理 | 中间件实例（Redis / 关系数据库）注册、分组、连接测试、凭据托管 |
| Redis 监控 | 实例指标（内存/OPS/命中率/连接/慢日志/复制）、Keyspace 分析、大 key/热 key 分析 |
| Redis 数据管理 | key 检索（SCAN）、详情查看、编辑、删除、TTL 管理、批量操作 |
| 数据库监控 | 连接池（Druid）指标、慢 SQL、会话/锁、表容量、QPS/TPS |
| 数据库数据管理 | 元数据浏览（库/表/字段/索引）、表数据分页浏览、受控 SQL 控制台（只读优先） |
| 微服务监控 | 服务实例列表（对接 Nacos 注册中心）、健康状态、Actuator 指标聚合、日志级别动态调整 |
| 监控大盘 | 全局概览仪表盘 |
| 告警中心 | 告警规则、告警记录、通知渠道对接 |

**不纳入范围（本期）**：

- 服务器/操作系统级监控（CPU/磁盘/网络）——建议沿用 Prometheus + Grafana 体系，本模块仅预留链接跳转；
- 全链路追踪详情页——对接已有 SkyWalking，本模块只做入口集成；
- 容器/K8s 监控；
- 业务指标自定义看板（后续迭代）；
- MQ（RocketMQ）、MongoDB 的监控与数据管理（架构上预留扩展点，二期实现）。

### 1.4 术语

| 术语 | 说明 |
|------|------|
| 监控对象 / 实例 | 一个被监控的中间件实体，如某个 Redis standalone/cluster、某个 PostgreSQL 库 |
| 应用 | 一个微服务（如 carlos-auth），与多个监控对象存在「使用」关联 |
| 采集器（Collector） | 监控服务端定时拉取实例指标的组件 |
| 数据源凭据 | 实例的地址、账号、密码等连接信息，加密存储 |

## 2. 总体设计概述

### 2.1 产品定位与模块归属

新增独立集成模块 **`carlos-monitor`**（位于 `carlos-integration/` 下），采用与 carlos-audit 一致的四件套结构，作为平台级基础服务独立部署；菜单通过 SysMenu 注册到「系统管理」下，前端页面落在 `manage/monitor/`。

```
carlos-monitor/
├── carlos-monitor-api      # Feign 接口 + AO
├── carlos-monitor-bus      # 业务实现（采集、存储、查询、数据管理）
├── carlos-monitor-boot     # 单体启动
└── carlos-monitor-cloud    # 微服务启动
```

> 说明：监控模块需要直连各中间件并承载高频指标写入，独立于 carlos-system 部署可避免影响系统管理服务；菜单归属「系统管理」仅是权限/导航层面的组织方式。

### 2.2 总体架构

```
┌─────────────────────────── carlos-framework-ui ───────────────────────────┐
│ 系统管理 › 监控中心（manage/monitor/…）                                    │
└──────────────┬───────────────────────────────────────────────────────────┘
               │ Bearer（经 carlos-gateway 鉴权）
┌──────────────▼───────────────────────────────────────────────────────────┐
│ carlos-monitor                                                            │
│  ├─ 实例注册中心（CRUD + 连接测试 + 凭据 SM2 加密托管）                     │
│  ├─ 采集调度（对接 carlos-job，按实例×指标项分片调度）                      │
│  │    ├─ RedisCollector（INFO / SLOWLOG / MEMORY / SCAN 抽样）            │
│  │    ├─ DbCollector（Druid Stat / information_schema / 会话与锁）        │
│  │    └─ ServiceCollector（Nacos 实例 + Actuator 端点聚合）               │
│  ├─ 指标写入（Disruptor 环形缓冲 → ClickHouseBatchWriter，复用 audit 模式）│
│  ├─ 数据管理代理（RedisProxy / SqlConsole，连接池化 + 安全拦截）           │
│  ├─ 告警引擎（规则匹配 → carlos-message 通知）                             │
│  └─ 操作审计埋点（→ carlos-audit）                                        │
└──────┬───────────────┬──────────────────┬───────────────────────────────┘
       │ 凭据连接       │ HTTP              │ 注册中心/Actuator
  ┌────▼────┐    ┌──────▼──────┐     ┌──────▼───────┐
  │ Redis×N │    │ PostgreSQL / │     │ Nacos + 各微 │
  │（多实例）│    │ MySQL / DM×N │     │ 服务 Actuator│
  └─────────┘    └─────────────┘     └──────────────┘

存储：元数据 → 框架主库（MyBatis-Plus）；时序指标 → ClickHouse
```

关键架构决策：

1. **Agent-less 主动拉取**：监控端使用托管凭据主动连接各实例采集，不要求业务服务改造；业务服务侧指标（JVM/HTTP）通过已广泛引入的 Actuator 端点拉取。
2. **多实例一等公民**：监控对象以「实例」为粒度注册，实例与应用为多对多关联，天然支持「一个应用多个 Redis / 多个数据库」。
3. **指标与元数据分库**：高频时序指标写 ClickHouse（复用 carlos-audit 的 Disruptor + JSONEachRow 批量写 + 落盘兜底模式），实例/规则/关联等元数据走主库 MyBatis-Plus。
4. **采集调度复用 carlos-job**：采集任务注册为 job 中心的任务，天然获得分片、失败重试、执行日志能力。
5. **数据管理走代理而非直连**：所有 Redis/SQL 数据操作由 carlos-monitor 服务端代理执行，统一做权限校验、SQL/命令拦截、审计埋点。

### 2.3 用户角色

| 角色 | 权限概要 |
|------|----------|
| 系统管理员 | 全部功能，含实例注册、数据管理写操作、告警规则维护 |
| 运维人员 | 监控查看、告警处理、Redis/DB 数据只读查询、受控写操作 |
| 开发人员 | 查看自己负责应用的监控视图、慢 SQL、只读数据查询 |
| 审计人员 | 只读查看操作审计记录 |

角色通过现有菜单权限（SysMenu + SysOperation 按钮级权限点）+ 实例级数据权限（按应用/分组授权）控制。

## 3. 功能需求

需求编号规则：`FR-MON-<域><序号>`；优先级：P0 必须 / P1 重要 / P2 增强。

### 3.1 FR-MON-A 监控对象管理（实例注册中心）

#### FR-MON-A1 中间件实例注册（P0）

运维人员将 Redis / 数据库实例登记进监控中心。

- 支持实例类型：`REDIS_STANDALONE`、`REDIS_CLUSTER`、`REDIS_SENTINEL`、`POSTGRESQL`、`MYSQL`、`DM`（达梦）、`CLICKHOUSE`（监控指标存储自身也可被监控）。
- 登记字段：实例名称、类型、环境（dev/test/prod）、连接地址（host:port 列表）、数据库编号/库名、账号、密码、分组、标签、关联应用（多选）、采集开关、采集间隔（默认 30s，可配 10s~10min）、超时参数、备注。
- Redis cluster/sentinel 支持多节点地址与拓扑自动发现（发现从节点/分片）。
- **连接测试**：保存前必须支持「测试连接」按钮，返回连通性、版本、耗时；cluster 模式返回各节点状态。
- 凭据安全：密码使用 SM2/SM4 国密算法（复用 carlos-spring-boot-starter-encrypt）加密落库；接口返回与日志中密码字段永不明文展示；页面密码字段不回显。
- 实例停用：支持禁用采集与数据管理入口，保留历史数据。

#### FR-MON-A2 实例与应用关联（P0）

- 实例与应用多对多关联，支持按「应用」视角聚合查看其全部中间件。
- 提供「自动发现」辅助：读取目标应用 Nacos 配置（spring.data.redis / spring.datasource.dynamic.datasource）生成待确认实例草稿，人工确认凭据后入库（P1）。

#### FR-MON-A3 实例分组与授权（P1）

- 实例支持分组（按环境/业务线），角色可按组授权，实现「开发只能看自己应用的实例」。

### 3.2 FR-MON-B 监控大盘（P1）

- 全局总览卡片：实例总数、健康/异常实例数、当前告警数（按级别）、采集任务运行状态。
- 关键指标趋势图：各实例内存使用率、Redis OPS、DB QPS、慢查询数 Top N（时间范围可选 1h/6h/24h/7d）。
- 应用视角：选中应用后展示其关联的全部中间件与健康状态一览。
- 异常实例/最新告警滚动列表，点击跳转详情。
- 前端基于 ECharts，数据接口聚合查询 ClickHouse。

### 3.3 FR-MON-C Redis 监控（P0）

#### FR-MON-C1 实例运行指标（P0）

定时采集并可视化（图表 + 当前值），指标项：

| 分类 | 指标 |
|------|------|
| 内存 | used_memory、used_memory_rss、mem_fragmentation_ratio、maxmemory、used_memory_dataset、各 db keyspace（keys/expires/avg_ttl） |
| 性能 | instantaneous_ops_per_sec、expired/evicted_keys、keyspace_hits/misses（命中率）、total_commands_processed |
| 连接 | connected_clients、blocked_clients、rejected_connections、maxclients |
| 持久化 | rdb_last_save_time、rdb_changes_since_last_save、aof_enabled、aof_last_rewrite_time、aof_current_size |
| 复制 | role、connected_slaves、master_link_status、master_last_io_seconds_ago、复制偏移量差值（lag） |
| 集群 | cluster_enabled、cluster_state、各 slot 分布、节点列表与角色（cluster 模式） |

- cluster/sentinel 模式按节点拆分展示，支持节点切换。
- 指标保留：ClickHouse 中原始粒度保留 7 天，小时聚合保留 90 天（TTL 自动清理）。

#### FR-MON-C2 慢查询（Slowlog）（P0）

- 定时拉取 `SLOWLOG GET`，列表展示：时间、耗时（μs）、命令、客户端地址、节点。
- 支持按耗时阈值/时间段/节点过滤，命令自动脱敏（value 参数以 `***` 替换）。

#### FR-MON-C3 大 Key / 热 Key 分析（P1）

- **大 Key 扫描**：后台任务按 batch SCAN + `MEMORY USAGE`（不支持时降级 `STRLEN`/类型长度），输出 Top N 大 key 报告（key、类型、内存、元素数、TTL、采样时间），支持手动触发与定时（默认每日凌晨）。
- **热 Key 分析**：基于 `MONITOR` 采样（限时 10s 内、手动触发）或 LFU `OBJECT FREQ`（若实例开启 lfu 策略），输出访问频次 Top N。
- 分析报告持久化，支持历史对比；扫描过程限制并发与速率，避免影响生产实例。

### 3.4 FR-MON-D Redis 数据管理（P0）

> 所有写操作走服务端代理执行，强制权限校验 + 二次确认 + 审计。

#### FR-MON-D1 Key 浏览与检索（P0）

- 左侧 DB 选择（cluster 模式为节点/逻辑视图），SCAN 游标分页（禁止 KEYS *），支持 pattern 模糊（`user:*`）、类型过滤、每页条数选择。
- 大实例提示扫描进度与已扫描数，支持「继续加载」。
- key 列表展示：key 名、类型（string/hash/list/set/zset/stream）、TTL、内存占用（可开关，避免批量 MEMORY USAGE 开销）。

#### FR-MON-D2 Key 详情查看（P0）

- 按类型展示值：string（含 JSON 美化/格式化）、hash（field-value 表格，分页）、list/set/zset（分页 + score）、stream（条目分页）。
- 展示 TTL、类型、编码（OBJECT ENCODING）、内存占用；值内容默认脱敏规则可配（如字段名含 password/phone 时掩码）。

#### FR-MON-D3 Key 编辑与删除（P0）

- 修改：string 覆盖写、hash/list/set/zset 元素级增删改；修改 TTL（含设置永不过期）。
- 新增 key：选择类型后按表单录入。
- 删除：单个删除 / 选中批量删除 / 按 pattern 批量删除（**pattern 删除需输入 key 数量确认 + 走 UNLINK 异步删除 + 高危操作权限点**）。
- 所有写操作弹窗二次确认，记录操作前值快照进审计。

#### FR-MON-D4 导入导出（P2）

- 选中 key 导出 JSON/CSV；导入时冲突策略可选（跳过/覆盖），单次上限 1 万条。

### 3.5 FR-MON-E 数据库监控（P0）

#### FR-MON-E1 连接池与运行指标（P0）

框架已集成 Druid + dynamic-datasource，监控两个层面：

- **连接池**：active/maxActive/空闲数、等待线程数、等待耗时、池使用率、创建/销毁计数（通过 Druid StatManager 或 JDBC 代理拉取）。
- **数据库实例**：版本、运行时长、当前连接数（按状态细分）、QPS/TPS、慢查询数、缓存命中率；PostgreSQL 取 `pg_stat_activity`/`pg_stat_database`，MySQL 取 `performance_schema`/global status，DM 取对应动态视图（实现按 DbType 适配器隔离，首期支持 PostgreSQL + MySQL，DM 为 P1）。

#### FR-MON-E2 慢 SQL 分析（P0）

- 来源一（推荐）：Druid 慢 SQL 统计（已在连接池层采集，含 SQL 指纹、执行次数、最大/平均耗时）；
- 来源二：数据库自身慢查询日志/系统视图（P1）。
- 列表展示：SQL 指纹、样例 SQL（参数脱敏）、执行次数、平均/最大耗时、最近执行时间、关联数据源；支持时间范围与耗时阈值过滤。

#### FR-MON-E3 会话与锁（P1）

- 当前会话列表：会话 ID、用户、来源 IP、状态、当前 SQL、持续时长；支持 kill 会话（高危权限点 + 二次确认 + 审计）。
- 锁等待视图：阻塞链（谁阻塞谁）、锁对象、等待时长。

#### FR-MON-E4 容量分析（P1）

- 库/表级容量：表大小、索引大小、行数估计、增长趋势（每日采集快照）；Top N 大表报告。

### 3.6 FR-MON-F 数据库数据管理（P0）

#### FR-MON-F1 元数据浏览（P0）

- 库 → 模式/表 → 字段、类型、约束、索引、注释 的树形浏览；表 DDL 查看。
- 支持按表名/注释搜索（information_schema）。

#### FR-MON-F2 表数据浏览（P0）

- 选中表分页浏览（强制 LIMIT 分页，禁止全表拉取），支持按列等值/模糊条件过滤、排序。
- 大字段（TEXT/BLOB）截断展示，点击查看完整值；敏感列按配置脱敏。

#### FR-MON-F3 SQL 控制台（P1）

- 受控 SQL 执行器：
  - **默认只读模式**：仅允许 SELECT/EXPLAIN（SQL 解析白名单，禁止 DML/DDL/危险函数；多语句禁止；自动追加行数上限，默认 500，硬上限 5000）。
  - **写模式**（高危权限点 + 审批/二次确认 + 全量审计）：允许 UPDATE/DELETE，强制 WHERE 条件校验（无 WHERE 或恒真条件拒绝），默认禁用 DDL。
- 执行结果表格展示 + 导出 CSV；执行历史（含耗时、影响行数、执行人）留档。
- SQL 解析采用 Druid WallParser 或 JSqlParser（选型在技术设计阶段确定），严禁字符串拼接判断。

### 3.7 FR-MON-G 微服务监控（P1）

#### FR-MON-G1 服务实例列表（P1）

- 对接 Nacos 注册中心：服务名、实例数、健康实例数、各实例 IP:端口/版本/元数据/权重。
- 按服务查看其 Actuator 健康状态（UP/DOWN 及组件明细）。

#### FR-MON-G2 服务指标聚合（P1）

- 通过各实例 Actuator 端点聚合：JVM（堆/非堆/GC/线程数）、HTTP（QPS/RT 分位/错误率）、进程 CPU/内存、Tomcat/虚拟线程池水位。
- 支持多实例同图对比；指标写 ClickHouse。

#### FR-MON-G3 在线运维操作（P2）

- 动态调整日志级别（Actuator loggers 端点，带过期恢复）；
- 查看/触发 GC、线程 Dump（只读展示）；
- SkyWalking 链接跳转（按服务名带参跳到既有 SkyWalking UI）。

### 3.8 FR-MON-H 告警中心（P0）

#### FR-MON-H1 告警规则（P0）

- 规则定义：监控对象（实例/实例组/全部）+ 指标 + 条件（>、<、环比变化率）+ 阈值 + 持续周期（如连续 3 次采集）+ 告警级别（提示/警告/严重）+ 通知人/角色 + 通知渠道。
- 内置规则模板：Redis 内存使用率 >85%、命中率 <90%、主从断链、连接数 >80% maxclients；DB 连接池使用率 >85%、慢 SQL 突增、实例不可用；微服务实例 DOWN、错误率 >5%。

#### FR-MON-H2 告警触发与通知（P0）

- 采集数据到达后由告警引擎评估，触发后写告警记录并通过 **carlos-message** 发送（站内信/邮件/钉钉，渠道可配）。
- 支持告警静默（按实例+规则静默 N 小时）、告警收敛（同规则同实例未恢复前不重复轰炸，按升级策略重发）。
- 告警生命周期：触发 → 确认（认领）→ 恢复（自动检测恢复并通知）；记录处理人与处理备注。

### 3.9 FR-MON-I 审计与权限（P0）

- **操作审计**：所有数据管理写操作（Redis 写/删、SQL 写、kill 会话、实例凭据变更、告警规则变更）通过现有埋点体系上报 carlos-audit，内容包括操作人、实例、操作类型、命令/SQL 摘要、操作前快照、结果、耗时、来源 IP。
- **权限点设计**（注册为 SysOperation，挂到监控菜单下）：
  - `monitor:instance:view/add/edit/delete/test`
  - `monitor:redis:view`、`monitor:redis:data:view`、`monitor:redis:data:edit`、`monitor:redis:data:delete`（高危）、`monitor:redis:data:batch-delete`（高危）
  - `monitor:db:view`、`monitor:db:data:view`、`monitor:db:sql:readonly`、`monitor:db:sql:write`（高危）、`monitor:db:session:kill`（高危）
  - `monitor:service:view`、`monitor:alarm:view/rule/confirm`
- 高危权限点默认仅授予系统管理员；高危操作强制二次确认（输入实例名或影响条数）。

## 8. 约束与依赖

1. 采集端直连中间件，需保证 carlos-monitor 部署节点到各实例的网络可达与防火墙放行。
2. Redis 大 key 分析依赖 `MEMORY USAGE`（Redis ≥ 4.0），低于该版本降级处理并在页面标注。
3. 慢 SQL 来源一依赖 Druid 监控开关（`druid.stat`）在被监控应用侧开启；未开启时仅有实例级指标。
4. SQL 控制台写模式默认在 prod 环境实例上关闭（实例级开关），开启需管理员显式操作。
5. 凭据托管为可选：不允许托管的实例可配置「只监控（走业务应用 Actuator 暴露的只读信息），不开放数据管理」。

## 9. 验收标准（摘要）

- 可注册并同时监控 ≥ 3 个 Redis 实例与 ≥ 2 个不同类型数据库实例，大盘正确聚合展示；
- Redis 数据管理完成 key 查/改/删全流程且 carlos-audit 可查到对应审计记录；
- SQL 控制台只读模式拦截全部 DML/DDL 用例（提供测试用例集）；
- 配置 Redis 内存阈值规则后，模拟超阈值在 2 个采集周期内收到站内信告警；
- 停用任一被监控实例，其余实例采集与页面不受影响；
- 权限点生效：无 `monitor:redis:data:delete` 权限的用户调用删除接口返回 403。
