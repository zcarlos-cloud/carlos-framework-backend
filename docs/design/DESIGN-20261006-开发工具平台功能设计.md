## 1. 背景与目标

### 1.1 现状

`carlos-framework-backend/carlos-integration/carlos-tools` 是一个 **JavaFX 桌面程序**（入口 `com.carlos.fx.ToolsApplication`），内含：

- **代码生成器（codege）**：连数据库读表元数据 → 选表 → 选模板组 → FreeMarker 渲染 → 写本地磁盘。
- **工程生成器（projectge）**：表单填 Maven 坐标 → 渲染出单体 / 微服务多模块工程骨架 → 写本地磁盘。
- **GitLab 工具**：分支 / Issue / MR / 用户管理 + 报表导出（与上两者无依赖，本期不动）。
- **模板**：classpath 静态资源（`resources/codege/templates/` 4 组 107 个 `.ftl` + `resources/projectge/project-templates/` 2 组），启动时整体拷到本地临时目录。

**痛点**：只有本机能跑；模板改不了共享（改完只在自己机器上）；产物要手工拷到目标工程；新同事装环境成本高；**全程无任何 REST API、无任何数据库持久化**。

### 1.2 目标

1. 把 **代码生成器** 与 **工程生成器** 搬成管理后台的页面功能，团队共享。
2. 新增 **一级菜单「开发工具」**，下含：数据源管理、代码生成器、工程生成器、模板管理、模板在线编辑、生成记录。
3. 模板从「classpath 静态资源」变为「数据库托管 + 在线编辑 + 版本留痕」，模板成为团队资产。
4. 产物 **在线预览 + 打包 zip 下载**，不再写服务器磁盘。

### 1.3 范围

| 项 | 一期 | 二期（预留） |
|---|---|---|
| 代码生成器（在线预览 / zip 下载） | ✅ | |
| 工程生成器（在线预览 / zip 下载） | ✅ | |
| 模板组 / 模板文件管理 + 在线编辑 + 版本回滚 | ✅ | |
| 受管数据源（SM4 加密） | ✅ | |
| 生成记录 | ✅ | |
| 生成后直接推 GitLab 新仓库 / MR | | ✅ |
| 模板组导入导出（zip 上传/下载） | ✅（导出必做，导入可选） | |
| GitLab 工具 Web 化 | | ✅ |

## 2. 现状可复用度分析

**结论：`service` + `utils` + `entity` + 全部模板资源 ≈ 80% 逻辑可直接复用；`controller` 与 UI 组件必须重写；持久化层从零设计。**

### 2.1 可直接复用（纯逻辑，零 JavaFX）

| 复用项 | 原位置（`carlos-tools/src/main/java/com/carlos/fx/`） | 说明 |
|---|---|---|
| 代码生成引擎 | `codege/service/CodeGeneratorService.java` | 复制模板→注入包路径→读元数据→递归渲染；改造点见 §4.3 |
| Freemarker 封装 | `utils/TemplateUtil.java` | `getTemplatesBaseInfo` / `dealTemplateFile` / `createClassFile` |
| XML 解析 | `utils/XmlUtils.java` | `typeConverter.xml` → `Map<dbType, javaType>`；`template.xml` → `TemplateBaseInfo` |
| JDBC 元数据 | `utils/DatabaseUtil.java` | `testConnection` / `getSchemas` / `getTables` |
| 命名转换 | `utils/NameUtil.java` | `getClassNamePrefix` / `getCamelName` / `delPrefixToCamel` … |
| 项目生成引擎 | `projectge/service/ProjectGeneratorService.java` | `generateDir` 递归 + 4 个路径占位符替换 |
| 领域模型 | `codege/entity/*`、`config/CodeGenerateInfo`、`projectge/entity/ProjectInfo`、3 个枚举 | POJO，原样搬 |
| 类型映射 | `resources/codege/typeConverter.xml` | 原样搬 |
| 全部模板 | `resources/codege/templates/**`、`resources/projectge/project-templates/**` | 原样搬（先入种子 SQL，见 §5） |

### 2.2 必须重写

| 重写项 | 原因 |
|---|---|
| `CodeGeneratorController` / `ProjectGeneratorController` | 全是 `@FXML` 字段 + `TreeView` + `DirectoryChooser` + `Task`；改为 `@RestController` + JSON |
| `BaseController` / `MainController` / `ToolsApplication` | JavaFX / Spring-Boot-GUI 启动器 |
| `utils/AsyncTaskUtil` / `DialogUtil` / `FxUtil` | JavaFX |
| `common/component/*`（DatabaseConnectionPanel / TableSelectionView / DiffViewer / ProgressDialog / ServerConfigDialog） | JavaFX 组件；**`DiffViewer` 在原工程中从未被生成流程调用**，"生成前 diff" 是新增能力，前端实现 |
| `resources/fxml/**`、`resources/css/**`、JavaFX 依赖 | 桌面 UI 栈，`pom.xml:86-133` 全部去掉 |
| `utils/ResourceUtil.copyResourceFile2Temp` | 模板改由 DB 提供，不再需要解包 classpath |

### 2.3 关键差异（原实现 vs Web 化）

| 维度 | 原桌面 | Web 版 |
|---|---|---|
| 模板来源 | classpath → 本地临时目录 | **数据库** → 请求级临时目录 |
| 数据库连接 | 前端表单传连接串，后端直连 | **受管数据源表**（SM4 加密），后端按 id 取 |
| 产物去向 | 写本地输出目录 | **内存 → zip 流下载** |
| 模板编辑 | 用户自己改临时目录文件 | **页面在线编辑，入库** |
| 持久化 | 无 | 6 张表（见库表设计） |
| 并发隔离 | 单机单人 | 多用户并发，**按请求隔离临时目录** |

## 3. 总体架构

### 3.1 部署视图

```
carlos-framework-ui (Vue3, :5173)
        │  前端 service 走 /devkit/**
        ▼
carlos-gateway (:9510)  路由: id=carlos-devkit, Path=/devkit/**, SelectStripPrefix=1
                        （定义在网关模块 application.yml + Nacos common.yml 两处，见 §7）
        │  lb://carlos-devkit
        ▼
carlos-devkit-boot (:9520)  ──── PostgreSQL（dev_* 6 张表）
        │                   └── JDBC ──▶ 目标业务库（受管数据源，只读元数据）
        └── 临时目录 ${java.io.tmpdir}/carlos-devkit/{requestId}/  （渲染沙箱，用完即删）
```

> **网关前缀注意**：`SelectStripPrefixGatewayFilterFactory` 是**选择性**剥离——只对 Swagger 与 `/*/app/enum(s)` 白名单生效，**业务路径不剥前缀**。因此后端 Controller 的 `@RequestMapping` **必须自带 `devkit/` 前缀**（照抄 `MessageTemplateController` 的 `@RequestMapping("message/template")` 写法）。

### 3.2 技术决策（已确认）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 后端落点 | **新建 `carlos-devkit` 服务**（`carlos-integration/` 下 api/bus/cloud/boot 四层） | 与内核式服务解耦；独立端口 / 路由 / 配置；生成引擎从 `carlos-tools` 迁入 |
| 模板存储 | **全部入库**，生成时物化到临时目录 | 支持在线编辑 / 版本回滚 / 启用停用 / 审计；多实例部署天然共享 |
| 产物交付 | **在线预览 + zip 下载** | 不写服务器磁盘，无路径 / 权限风险；`@NoWrap` 直出二进制流 |
| 目标库 | **受管数据源表 + SM4 加密** | 复用 `carlos-monitor` 的 `CredentialCipher` 做法；避免任意库直连（SSRF / 凭据泄露） |

### 3.3 与 `carlos-tools` 桌面的关系

`carlos-tools` **保持不动**（继续作为开发者本地工具），`carlos-devkit` 以「迁移 + 改造」方式复制其引擎代码。不采用抽取 `tools-core` 共用的方案——因为桌面端的模板加载（classpath）与 Web 端（DB）本质不同，强行共用会引入双向条件分支，收益低于成本。

> 一期完成后，若桌面端确定下线，可再删除 `carlos-tools` 或将其降级为「仅 GitLab 工具」。

### 4.3 引擎改造点（逐条）

| # | 改造 | 原实现 | 新实现 |
|---|---|---|---|
| 1 | **模板装载** | `ResourceUtil.copyResourceFile2Temp("codege", tmp)` 解包 classpath | `TemplateMaterializer.materialize(groupId, tmpDir)`：按 `group_id` 查 `dev_template`，按 `file_path` 建目录、写文件（`file_type=2` 的静态资源同样落盘） |
| 2 | **模板元数据** | 读 `template.xml` 反序列化 `TemplateBaseInfo` | 直接读 `dev_template_group` 行（`name` / `describe` / 字段配置已拆列存） |
| 3 | **包路径注入** | `moveTemplate2PackagePath()` 把 `src/main/java/**` 挪到 `temp/{包路径}`，再改名 `java` | **保留**（物化后逻辑不变）；但注意目标是**临时目录**，不再有"必须先拷贝再改"的限制 |
| 4 | **渲染** | 递归遍历，`.ftl` 渲染后**删除模板文件** | 递归遍历，渲染结果写入 `Map<String /*相对路径*/, byte[]>`（**内存收集，不落盘**）；目录结构保留至最终 zip |
| 5 | **DB 元数据** | `DatabaseInfo.buildUrl()` + 前端传的 host/port/user/pwd | `DataSourceService` 按 `dsId` 取实体 → `CredentialCipher.decrypt` → 构造连接；**只读元数据**（`DatabaseMetaData`），不执行任何业务 SQL |
| 6 | **并发隔离** | 单机单实例，固定 `tmp/codege_temp` | **每个生成请求一个临时目录** `${tmp}/carlos-devkit/{requestId}/`，`try/finally` 删除；同一模板组并发不互相覆盖 |
| 7 | **名称占位符** | `[base]` / `[for]`（`CodeDirectEnum`）、`[ArtifactId]` / `[Package]` / `[CamelName]` / `[UnderLineName]`（`ProjectDirectEnum`） | **完全保留**，模板语义不变，迁移零成本 |
| 8 | **工程生成模板加载** | `ResourceUtil.getResource(...)`（jar 下会失败，属原实现缺陷） | 统一走 `TemplateMaterializer`，顺带修掉该缺陷 |
| 9 | **渲染引擎统一** | codege 用 Freemarker `Configuration`；projectge 用 Hutool `TemplateEngine` | **统一 FreeMarker**（Hutool 默认实现也是 Freemarker，行为一致；统一后可统一施加安全策略） |
| 10 | **产物下载** | 弹窗问"是否打开目录" | `ZipOutputStream` → `ByteArrayOutputStream` → `ResponseEntity<byte[]>` + `@NoWrap` |

### 4.5 安全设计（重点）

> 本模块同时具备「任意 JDBC 连接」与「用户可写模板（服务端求值）」两个高危面，安全设计必须先于功能落地。

| 风险 | 措施 |
|---|---|
| **模板 SSTI / RCE**（FreeMarker 模板可由用户在线编辑 → 可执行任意 Java） | 渲染用**独立** `freemarker.template.Configuration`：<br>① `setNewBuiltinClassResolver(TemplateClassResolver.SAFER_RESOLVER)`（禁 `?new`）<br>② `setAPIBuiltinEnabled(false)`（禁 `?api`）<br>③ `setSetting(Configuration.SQL_DATE_TIME_TIME_ZONE_KEY, …)` 无影响但统一显式设置<br>④ 不暴露 `ObjectConstructor` / `Execute` |
| **渲染炸弹**（`<#list>` 死循环 / 超大输出） | 渲染超时（`Template#process` 走带超时的 `Writer` + 线程池 `Future.get(timeout)`）；单文件输出上限（如 2MB）；单次生成文件数上限 |
| **路径穿越**（`file_path` 含 `..` / 绝对路径 / 盘符） | `TemplatePathValidator`：拒绝绝对路径、`..`、`:`、以 `/` 开头；`Paths.get(base).resolve(p).normalize()` 后必须 `startsWith(base)` |
| **zip 炸弹 / 超大产物** | 预览与 zip 均设总大小上限（默认 50MB）与文件数上限（默认 2000），超限抛业务异常 |
| **任意库直连** | 数据源受管（`dev_datasource`）+ 建议使用**只读账号**；连接超时（默认 5s）、语句超时；仅调 `DatabaseMetaData`，不执行用户 SQL |
| **凭据泄露** | 密码 SM4 加密（复用 `com.carlos.monitor.instance.connection.CredentialCipher` 的 `EncryptUtil` 思路，本模块自建 `CredentialCipher`）；**列表/详情不下发密码**；日志脱敏；`carlos.encrypt.sm4.enabled=false` 时必须启动告警（原样返回即明文） |
| **权限** | 开发工具属高危功能：所有端点要求 `perm_code` 前缀 `devkit:*`；模板保存 / 生成 / 删除数据源建议额外要求开发角色 |
| **`@NoWrap` 漏加** | 下载端点漏加会把 `byte[]` 包成 `Result` 信封 → HTTP 200、文件名正确、**文件打不开**。必须写端点测试钉死（参照 `WorkflowDefinitionExportEndpointTest`） |
| **临时目录残留** | `try/finally` 强制删除；启动时清理上次残留的 `${tmp}/carlos-devkit/*` |

## 9. 风险与遗留

| 风险 | 等级 | 说明 / 缓解 |
|---|---|---|
| 模板在线编辑 = 服务端代码执行 | **CRITICAL** | §4.5 的 Freemarker 安全三件套 + 渲染超时是**上线前置条件**，不是可选优化 |
| 任意库直连 | **HIGH** | 受管数据源 + 只读账号建议 + 连接/语句超时；后续可加库白名单 |
| `@NoWrap` 漏加导致下载文件损坏 | **HIGH** | 端点测试钉死 |
| 大表 / 大库元数据读取慢 | MEDIUM | 表清单分页 + 关键字过滤；列元数据按表懒加载 |
| 模板版本表膨胀 | MEDIUM | 每次保存落一版；可加保留策略（如每模板保留最近 50 版） |
| 迁移期间模板双份（桌面 classpath vs DB） | MEDIUM | 一期以 DB 为准；桌面端模板冻结，M2 后不再同步 |
| 多实例临时目录 | LOW | 每请求独立目录 + `finally` 清理；无需共享存储 |
| `carlos-tools` 是否下线 | LOW | 一期不动，二期评估 |
