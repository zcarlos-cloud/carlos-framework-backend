## 1. 背景与问题

### 1.1 现状

Carlos Framework 各微服务通过 `carlos-spring-boot-starter-web` 提供的 `/app/enum`、`/app/enums` 接口暴露本地枚举：

| 接口     | 方法  | 路径           | 描述                 |
|--------|-----|--------------|--------------------|
| 所有枚举字典 | GET | `/app/enums` | 获取全部枚举字典列表         |
| 单个枚举详情 | GET | `/app/enum`  | 参数 `name`，获取指定枚举详情 |

### 1.2 问题

各微服务的 Controller 前缀不一致，通过 Gateway 访问时产生路径差异：

| 微服务            | Controller 前缀 | 枚举接口路径            |
|----------------|---------------|-------------------|
| carlos-system  | `/sys/xxx`    | `/sys/app/enum`   |
| carlos-org     | `/org/xxx`    | `/org/app/enum`   |
| carlos-auth    | `/auth/xxx`   | `/auth/app/enum`  |
| carlos-message | `/msg/xxx`    | `/msg/app/enum`   |
| carlos-audit   | `/audit/xxx`  | `/audit/app/enum` |

**问题核心**：前端无法统一处理枚举的获取和使用。

## 2. 方案选型

### 2.1 业界四种模式

业界对跨微服务枚举/字典统一暴露有四种成熟方案：

| 模式                    | 中心化程度 | 代表框架                     |
|-----------------------|-------|--------------------------|
| 去中心化枚举 + 共享常量契约       | 最低    | 芋道（Yudao）、若依             |
| 配置中心托管（Nacos/Apollo）  | 低     | 阿里内部、Nacos 社区            |
| 独立字典服务（中台化）           | 高     | 大型政企、复杂 SaaS             |
| **API Gateway 聚合/路由** | **中** | **Spring Cloud Gateway** |

### 2.2 本方案选择

**选定方案：Gateway 路径路由 + 前端自动映射**

**核心思想**：利用 Spring Cloud Gateway 原生路径路由能力，前端通过 `useEnumStore` 自动拼接服务前缀，业务页面只传枚举名，无感知服务分布。

```
前端: GET /sys/app/enum?name=ConfigValueType
       ↓
Gateway: 匹配 /sys/** → StripPrefix=1 → lb://carlos-system
       ↓
后端: carlos-system 接收 /app/enum?name=ConfigValueType
```

### 2.3 选型理由

| 对比维度                   | 本方案              | Gateway 聚合            | 独立字典服务            |
|------------------------|------------------|-----------------------|-------------------|
| **性能**                 | ⭐⭐⭐⭐⭐ 直接路由       | ⭐⭐⭐ Gateway 内部二次 HTTP | ⭐⭐⭐ 跨服务调用         |
| **Gateway 改动**         | 恢复已有路由配置，**零代码** | 新增 Java 聚合 Controller | 无                 |
| **前端改动**               | Store 层加前缀映射     | 无（统一 `/app/enum`）     | 无                 |
| **服务自治**               | ✅ 完全自治           | ✅ 完全自治                | ❌ 依赖 dict-service |
| **故障隔离**               | ✅ 单服务枚举缺失不影响其他   | ✅ 同左                  | ❌ dict-service 单点 |
| **单体兼容**               | ✅ 所有前缀指向同一服务即可   | ✅ 同左                  | ✅ 同左              |
| **Spring Cloud 生态契合度** | **原生能力**         | 需自定义 Filter           | 需新增服务             |

**结论**：本方案在 Spring Cloud 生态下成本最低、性能最好、最符合 Gateway "只做路由转发"的设计职责。

## 3. 架构设计

### 3.1 请求时序

```
┌─────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  前端   │────→│   Gateway   │────→│  carlos-xxx │────→│ Application │
│         │     │             │     │   微服务     │     │ Controller  │
└─────────┘     └─────────────┘     └─────────────┘     └─────────────┘

请求: GET /sys/app/enum?name=ConfigValueType

Gateway 处理:
  1. Path=/sys/** 匹配 carlos-system 路由
  2. SelectStripPrefix=1 去掉 'sys'
  3. 转发到 lb://carlos-system/app/enum?name=ConfigValueType

后端处理:
  1. ApplicationController 接收 /app/enum
  2. EnumService 从内存缓存返回枚举详情
```

### 3.2 前端架构

```
┌─────────────────────────────────────────────┐
│              业务页面（Vue）                  │
│  enumStore.getEnumDesc('ConfigValueType', 1) │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│              useEnumStore（Pinia）            │
│  1. 查 ENUM_SERVICE_MAP['ConfigValueType']   │
│     → prefix = 'sys'                         │
│  2. 拼接 URL: /sys/app/enum?name=...         │
│  3. 调用 request() → Axios                   │
│  4. 缓存结果到 state.cache                   │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│              Axios Request                    │
│  baseURL + /sys/app/enum?name=ConfigValueType │
└─────────────────────────────────────────────┘
```

## 4. 后端实现

### 4.1 Gateway 路由配置

`carlos-integration/carlos-gateway/src/main/resources/application.yml`，在已有路由基础上补充/恢复：

```yaml
spring:
  cloud:
    gateway:
      routes:
        # === 已有路由（保持） ===
        - id: carlos-auth
          uri: lb://carlos-auth
          predicates:
            - Path=/auth/**,/oauth2/**
          filters:
            - SelectStripPrefix=1

        # === 新增/恢复枚举路由 ===
        - id: carlos-system
          uri: lb://carlos-system
          predicates:
            - Path=/sys/**
          filters:
            - SelectStripPrefix=1

        - id: carlos-org
          uri: lb://carlos-org
          predicates:
            - Path=/org/**
          filters:
            - SelectStripPrefix=1

        - id: carlos-message
          uri: lb://carlos-message
          predicates:
            - Path=/msg/**
          filters:
            - SelectStripPrefix=1

        - id: carlos-audit
          uri: lb://carlos-audit
          predicates:
            - Path=/audit/**
          filters:
            - SelectStripPrefix=1
```

**单体兼容**：如果某环境是单体部署，所有前缀指向同一个 `uri: lb://carlos-boot` 即可。

### 4.2 枚举扫描配置

各微服务在 `application.yml` 中开启枚举扫描（自行扫描本地枚举包）：

```yaml
carlos:
  boot:
    enums:
      enabled: true
      scan-package:
        # carlos-system
        - com.carlos.system.enums
        - com.carlos.system.dict.pojo.enums
```

### 4.3 枚举命名规范（强制）

为确保 `ENUM_SERVICE_MAP` 维护可控，约定 `@AppEnum(code)` **全局唯一**：

```java
// system 模块
@AppEnum(code = "ConfigValueType")
public enum ConfigValueType implements BaseEnum<Integer> {
    TEXT(1, "文本"),
    FILE(2, "文件");
    // ...
}

// org 模块 —— 建议加模块前缀避免冲突
@AppEnum(code = "OrgUserGender")
public enum OrgUserGenderEnum implements BaseEnum<Integer> {
    MALE(1, "男"),
    FEMALE(2, "女"),
    UNKNOWN(0, "保密");
    // ...
}

@AppEnum(code = "OrgUserState")
public enum OrgUserStateEnum implements BaseEnum<Integer> {
    ENABLE(1, "启用"),
    DISABLE(2, "禁用");
    // ...
}
```

**规范**：

- 模块独有的枚举，code 建议加模块标识前缀（`OrgXxx`、`AuthXxx`）
- 通用枚举（如 `EnableStatus`）放在 `carlos-spring-boot-core` 统一提供
- 严禁不同模块定义相同 `code` 的枚举

## 5. 前端实现

### 5.1 枚举服务映射

新建 `carlos-ui/src/constants/enum-service.ts`：

```typescript
/**
 * 枚举名 → 服务路径前缀映射
 *
 * 规则：
 * 1. 新增枚举时必须同步维护此映射
 * 2. 枚举 code 全局唯一，按模块划分前缀
 * 3. 未配置的枚举默认走 'sys' 前缀
 *
 * @example
 *   getEnumPrefix('ConfigValueType') → 'sys'
 *   getEnumPrefix('OrgUserState') → 'org'
 */
export const ENUM_SERVICE_MAP: Record<string, string> = {
  // ==================== system 模块 ====================
  ConfigValueType: 'sys',
  DictTypeEnum: 'sys',
  MenuType: 'sys',
  UserMessageType: 'sys',

  // ==================== org 模块 ====================
  OrgUserGender: 'org',
  OrgUserState: 'org',
  OrgRoleType: 'org',
  OrgRoleState: 'org',
  OrgPermissionType: 'org',
  OrgPermissionState: 'org',
  OrgDataScope: 'org',
  OrgDepartmentState: 'org',

  // ==================== auth 模块 ====================
  ClientState: 'auth',
  AlertType: 'auth',

  // ==================== message 模块 ====================
  MessageReceiverStatus: 'msg',

  // ==================== audit 模块 ====================
  AuditLogState: 'audit',
  AuditLogAuthType: 'audit',
  AuditLogCategory: 'audit',
  AuditLogPrincipalType: 'audit',
  AuditLogChangeType: 'audit',
  AuditLogBizChannel: 'audit',
  AuditLogAttachmentType: 'audit',
  AuditLogAuthProvider: 'audit',
};

/**
 * 根据枚举名获取服务前缀
 * @param name 枚举 code（@AppEnum 的 code 值）
 * @returns 服务路径前缀，未配置返回默认 'sys'
 */
export function getEnumPrefix(name: string): string {
  return ENUM_SERVICE_MAP[name] || 'sys';
}

/**
 * 批量注册枚举映射（用于动态扩展）
 * @param mappings 枚举名 → 前缀映射
 */
export function registerEnumMappings(mappings: Record<string, string>): void {
  Object.assign(ENUM_SERVICE_MAP, mappings);
}
```

### 5.2 枚举状态管理（Pinia Store）

新建 `carlos-ui/src/store/modules/enum/index.ts`：

```typescript
import { defineStore } from 'pinia';
import { request } from '@/service/request';
import { getEnumPrefix } from '@/constants/enum-service';

/** 枚举项数据结构 */
export interface EnumItem {
  code: string | number;
  desc: string;
  name: string;
}

/** 枚举 Store 状态 */
interface EnumState {
  /** 枚举缓存: { 枚举名: 枚举项列表 } */
  cache: Record<string, EnumItem[]>;
  /** 是否已全量加载 */
  loaded: boolean;
}

export const useEnumStore = defineStore('enum-store', {
  state: (): EnumState => ({
    cache: {},
    loaded: false
  }),

  getters: {
    /**
     * 获取枚举项列表
     * @param name 枚举名
     */
    getEnumItems: (state) => (name: string): EnumItem[] => {
      return state.cache[name] || [];
    },

    /**
     * 转换为 Select/Option 组件的 options 格式
     * @param name 枚举名
     */
    getEnumOptions: (state) => (name: string): { value: string; label: string }[] => {
      const items = state.cache[name] || [];
      return items.map(item => ({
        value: String(item.code),
        label: item.desc
      }));
    },

    /**
     * 根据 code 获取描述文本
     * @param name 枚举名
     * @param code 枚举 code 值
     */
    getEnumDesc: (state) => (name: string, code: string | number): string => {
      const items = state.cache[name] || [];
      const found = items.find(item => String(item.code) === String(code));
      return found?.desc || String(code);
    },

    /**
     * 根据 code 获取 name（枚举常量名）
     * @param name 枚举名
     * @param code 枚举 code 值
     */
    getEnumName: (state) => (name: string, code: string | number): string => {
      const items = state.cache[name] || [];
      const found = items.find(item => String(item.code) === String(code));
      return found?.name || String(code);
    },

    /**
     * 根据 code 获取完整枚举项
     * @param name 枚举名
     * @param code 枚举 code 值
     */
    getEnumItem: (state) => (name: string, code: string | number): EnumItem | undefined => {
      const items = state.cache[name] || [];
      return items.find(item => String(item.code) === String(code));
    }
  },

  actions: {
    /**
     * 按需加载单个枚举
     * @param name 枚举名（@AppEnum 的 code 值）
     */
    async loadEnum(name: string): Promise<EnumItem[]> {
      if (this.cache[name]) return this.cache[name];

      const prefix = getEnumPrefix(name);
      const { data, error } = await request<EnumItem[]>({
        url: `/${prefix}/app/enum`,
        method: 'get',
        params: { name }
      });

      if (!error && data) {
        this.cache[name] = data;
      }
      return this.cache[name] || [];
    },

    /**
     * 批量加载枚举
     * @param names 枚举名数组
     */
    async loadEnums(names: string[]): Promise<void> {
      await Promise.all(names.map(name => this.loadEnum(name)));
    },

    /**
     * 全量加载所有枚举（登录后调用一次）
     * 并发请求各服务的 /app/enums 接口，合并结果
     */
    async loadAllEnums(): Promise<void> {
      if (this.loaded) return;

      const services = ['sys', 'org', 'auth', 'msg', 'audit'];
      const results = await Promise.all(
        services.map(prefix =>
          request<Record<string, EnumItem[]>>({
            url: `/${prefix}/app/enums`,
            method: 'get'
          })
            .then(r => r.data || {})
            .catch(() => {
              console.warn(`[EnumStore] 加载服务[${prefix}]枚举失败`);
              return {};
            })
        )
      );

      this.cache = results.reduce(
        (acc, map) => ({ ...acc, ...map }),
        this.cache
      );
      this.loaded = true;
    },

    /**
     * 清空缓存（如用户切换租户时）
     */
    clearCache() {
      this.cache = {};
      this.loaded = false;
    }
  }
});
```

### 5.3 组合式函数（可选简化封装）

新建 `carlos-ui/src/composables/use-enum.ts`：

```typescript
import { computed } from 'vue';
import { useEnumStore } from '@/store/modules/enum';
import type { EnumItem } from '@/store/modules/enum';

/**
 * 枚举组合式函数
 * 简化页面中使用枚举的样板代码
 *
 * @example
 * const { options, desc, load } = useEnum('ConfigValueType');
 * onMounted(load);
 * // template: <ASelect :options="options" />
 */
export function useEnum(name: string) {
  const enumStore = useEnumStore();

  const items = computed(() => enumStore.getEnumItems(name));
  const options = computed(() => enumStore.getEnumOptions(name));
  const loaded = computed(() => !!enumStore.cache[name]);

  const load = () => enumStore.loadEnum(name);
  const desc = (code: string | number) => enumStore.getEnumDesc(name, code);
  const item = (code: string | number): EnumItem | undefined =>
    enumStore.getEnumItem(name, code);

  return {
    items,
    options,
    loaded,
    load,
    desc,
    item
  };
}

/**
 * 批量枚举组合式函数
 *
 * @example
 * const { loadAll } = useEnums(['ConfigValueType', 'OrgUserState']);
 * onMounted(loadAll);
 */
export function useEnums(names: string[]) {
  const enumStore = useEnumStore();

  const loadAll = () => enumStore.loadEnums(names);

  return {
    loadAll,
    getOptions: (name: string) => enumStore.getEnumOptions(name),
    getDesc: (name: string, code: string | number) => enumStore.getEnumDesc(name, code)
  };
}
```

## 6. 使用规范

### 6.1 页面中使用枚举

#### 方式一：按需加载（推荐）

```vue
<script setup lang="ts">
import { useEnumStore } from '@/store/modules/enum';

const enumStore = useEnumStore();

onMounted(() => {
  enumStore.loadEnum('ConfigValueType');
  enumStore.loadEnum('OrgUserState');
});

// 表格列渲染
const columns = [
  {
    key: 'valueType',
    title: '值类型',
    customRender: ({ record }) => enumStore.getEnumDesc('ConfigValueType', record.valueType)
  },
  {
    key: 'state',
    title: '用户状态',
    customRender: ({ record }) => {
      const desc = enumStore.getEnumDesc('OrgUserState', record.state);
      const colorMap: Record<string, string> = { '1': 'success', '2': 'error' };
      return h(Tag, { color: colorMap[String(record.state)] }, () => desc);
    }
  }
];

// 表单下拉选择
const valueTypeOptions = computed(() => enumStore.getEnumOptions('ConfigValueType'));
</script>

<template>
  <ASelect v-model:value="formModel.valueType" :options="valueTypeOptions" placeholder="请选择值类型" />
</template>
```

#### 方式二：使用组合式函数（更简洁）

```vue
<script setup lang="ts">
import { useEnum } from '@/composables/use-enum';

const { options: valueTypeOptions, load: loadValueType } = useEnum('ConfigValueType');
const { options: userStateOptions, load: loadUserState } = useEnum('OrgUserState');

onMounted(() => {
  loadValueType();
  loadUserState();
});
</script>

<template>
  <ASelect v-model:value="formModel.valueType" :options="valueTypeOptions" />
  <ASelect v-model:value="formModel.state" :options="userStateOptions" />
</template>
```

#### 方式三：登录后全量加载

```typescript
// src/store/modules/auth/index.ts 或登录逻辑中
import { useEnumStore } from '@/store/modules/enum';

async function handleLoginSuccess() {
  // ... 其他登录后初始化

  // 全量加载枚举（适合枚举总量不多的场景）
  const enumStore = useEnumStore();
  await enumStore.loadAllEnums();
}
```

### 6.2 与硬编码枚举的协作策略

项目中允许两种策略共存：

| 策略            | 适用场景      | 示例                               |
|---------------|-----------|----------------------------------|
| **动态加载**（本方案） | 可能变动的业务枚举 | `ConfigValueType`、`OrgUserState` |
| **前端硬编码**     | 绝对稳定的通用枚举 | `Gender`、`YesNo`、`EnableStatus`  |

硬编码枚举仍放在 `src/constants/business.ts`：

```typescript
// 绝对稳定的枚举，无需后端接口
export const genderRecord: Record<string, App.I18n.I18nKey> = {
  '0': 'common.gender.unknown',
  '1': 'common.gender.male',
  '2': 'common.gender.female'
};
```

### 6.3 新增枚举的 checklist

后端新增枚举时，前后端需同步：

- [ ] 后端：在对应模块创建 Enum 类，标注 `@AppEnum(code = "Xxx")`
- [ ] 后端：确保 `code` 全局唯一（建议加模块前缀）
- [ ] 前端：在 `enum-service.ts` 的 `ENUM_SERVICE_MAP` 中注册映射
- [ ] 前端：在页面中使用 `useEnumStore.loadEnum('Xxx')` 加载

## 8. 附录：与其他方案的对比

### 8.1 四方案总览

| 维度               | **本方案（路径路由）** | Gateway 聚合         | 单体统一扫描   | 前端直连        |
|------------------|---------------|--------------------|----------|-------------|
| 部署模式             | 微服务           | 微服务                | 单体       | 微服务         |
| Gateway 改动       | 恢复路由配置        | 新增聚合 Controller    | 无        | 无           |
| 前端改动             | Store 加前缀映射   | 无（统一 `/app/enum`）  | 无        | Store + 多实例 |
| 网络开销             | 最低（直接路由）      | 中（Gateway 二次 HTTP） | 最低（本地内存） | 低           |
| 服务故障隔离           | ✅ 单服务不影响其他    | ✅ 同左               | ❌ 单体挂全挂  | ✅ 同左        |
| 枚举全局唯一           | 需要            | 需要                 | 需要       | 需要          |
| 维护成本             | **低**         | 中                  | 低        | 高           |
| Spring Cloud 契合度 | **原生能力**      | 需自定义代码             | 不涉及      | 不涉及         |

### 8.2 各方案架构图
