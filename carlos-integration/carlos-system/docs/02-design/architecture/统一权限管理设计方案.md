## 一、现状诊断

### 1.1 已有基础

| 维度       | 已有内容                                                                                                |
|----------|-----------------------------------------------------------------------------------------------------|
| **菜单**   | `system.menu` 模块，`sys_menu` + `sys_menu_operate`。菜单树结构完整，有路由/组件/icon                                |
| **资源**   | `system.resource` 模块，`sys_resource_category` + `sys_resource`。启动时扫描 `@Tag`/`@Operation` 自动生成 API 列表 |
| **角色**   | `org` 模块，`org_role` + `org_user_role`，用户角色关联                                                        |
| **后端鉴权** | Gateway `OAuth2AuthorizationFilter` + 服务层 `CarlosPermissionEvaluator` + Redis/Caffeine 多级缓存         |
| **认证**   | carlos-auth OAuth2 Authorization Server，JWT Token 携带 `user_id`, `role_ids`, `tenant_id`             |
| **前端路由** | Soybean Admin 支持 static/dynamic 双模式；authStore 已有 `buttons: []` 定义                                   |

### 1.2 核心问题

| 问题                  | 说明                                                                                                                          |
|---------------------|-----------------------------------------------------------------------------------------------------------------------------|
| **数据重复**            | `sys_menu_operate` 和 `sys_resource` 都存了 `path` + `method`，自动扫描的 API 和手动维护的操作是两份数据，不同步                                       |
| **无权限码桥梁**          | `sys_resource` 只有 API 元信息，没有 `perm_code`。`sys_menu_operate` 有 `operate_code` 但和 `sys_resource` 无关联。前端按钮和后端 API 无法通过同一套权限码打通 |
| **类型语义混乱**          | `MenuOperate.operate_type` 是字符串，`SysResourceType` 定义的是按钮/链接/列表/其他，两者不是同一套枚举                                                 |
| **resource 不被鉴权消费** | `sys_resource` 数据仅供管理界面查看，鉴权不走它，Swagger/Knife4j 已经能展示 API 文档                                                                |
| **前端未对接**           | `/route/getUserRoutes` 未实现后端对接，按钮权限用硬编码模拟数据                                                                                 |

## 二、设计目标

1. **删除冗余**：`sys_resource` + `sys_resource_category` 是冗余的，删除
2. **统一操作**：按钮和 API 本质都是"一个操作"，合一管理
3. **权限码桥梁**：`perm_code` 是唯一权限标识，角色授权一次同时控制前后端
4. **菜单独立**：菜单只管前端导航，不承载权限语义
5. **前端对接**：动态路由从 `sys_menu` 获取，按钮权限从 `sys_operation` 获取
6. **Token 精简**：JWT 只带身份标识，权限走缓存

## 三、数据模型

### 3.1 sys_menu（前端导航）

纯前端菜单树，不承载权限语义。

```sql
CREATE TABLE sys_menu (
    id                  BIGINT PRIMARY KEY COMMENT '主键',
    parent_id           BIGINT DEFAULT 0 COMMENT '父级ID，0为根',
    menu_name           VARCHAR(100) COMMENT '菜单名称',
    route_path          VARCHAR(200) COMMENT '前端路由path',
    route_name          VARCHAR(100) COMMENT '路由name，前端匹配用',
    icon                VARCHAR(100) COMMENT '前端图标',
    icon_type           TINYINT DEFAULT 1 COMMENT '图标类型：1=iconify, 2=local',
    meta                VARCHAR(500) COMMENT '菜单配置（JSON扩展）',
    component           VARCHAR(200) COMMENT '目标组件',
    url                 VARCHAR(200) COMMENT '请求地址',
    menu_status         TINYINT DEFAULT 1 COMMENT '状态：1=启用, 2=禁用',
    remark              VARCHAR(255) COMMENT '备注',
    menu_level          INT COMMENT '菜单级数',
    order_num           INT DEFAULT 0 COMMENT '菜单排序',
    hide_in_menu        TINYINT DEFAULT 0 COMMENT '是否在菜单中隐藏：0否 1是',
    menu_category       TINYINT DEFAULT 1 COMMENT '菜单类别：1=目录, 2=菜单',
    client_type         VARCHAR(20) DEFAULT 'PC' COMMENT '客户端类型：PC/MOBILE/ALL',
    i18n_key            VARCHAR(100) COMMENT '国际化key',
    keep_alive          TINYINT DEFAULT 0 COMMENT '是否缓存页面：0否 1是',
    constant            TINYINT DEFAULT 0 COMMENT '是否常量路由：0否 1是',
    href                VARCHAR(200) COMMENT '外链地址',
    active_menu         VARCHAR(100) COMMENT '高亮菜单路由名',
    multi_tab           TINYINT DEFAULT 0 COMMENT '是否多标签页：0否 1是',
    fixed_index_in_tab  INT COMMENT '标签页固定索引',
    route_query         JSON COMMENT '路由query参数',
    create_by           BIGINT COMMENT '创建人',
    update_by           BIGINT COMMENT '修改人',
    is_deleted          TINYINT DEFAULT 0 COMMENT '逻辑删除：0否 1是',
    create_time         DATETIME COMMENT '创建时间',
    update_time         DATETIME COMMENT '修改时间',
    INDEX idx_parent (parent_id),
    INDEX idx_route_name (route_name),
    INDEX idx_menu_status (menu_status),
    INDEX idx_menu_category (menu_category)
);
```

### 3.2 sys_operation（统一操作表）

**按钮和 API 合一**。核心表，权限码 `perm_code` 是桥梁。

```sql
CREATE TABLE sys_operation (
    id              BIGINT PRIMARY KEY COMMENT '主键',
    op_type         TINYINT NOT NULL COMMENT '操作类型：1=按钮, 2=API',
    menu_id         BIGINT COMMENT '所属菜单（按钮必填，API可选）',
    op_name         VARCHAR(100) NOT NULL COMMENT '操作名称，如"新增用户"',
    perm_code       VARCHAR(100) NOT NULL COMMENT '权限码，如 user:create',
    icon            VARCHAR(100) COMMENT '图标（仅按钮）',
    sort            INT DEFAULT 0 COMMENT '排序',
    api_path        VARCHAR(500) COMMENT 'API路径（仅API）',
    api_method      VARCHAR(10) COMMENT 'HTTP方法（仅API）',
    auto_scan       TINYINT DEFAULT 0 COMMENT '是否自动扫描生成：0否 1是（仅API）',
    state           TINYINT DEFAULT 1 COMMENT '状态：0禁用 1启用',
    is_deleted      TINYINT DEFAULT 0 COMMENT '逻辑删除',
    create_by       BIGINT COMMENT '创建人',
    update_by       BIGINT COMMENT '修改人',
    create_time     DATETIME,
    update_time     DATETIME,
    UNIQUE KEY uk_perm_code (perm_code),
    INDEX idx_menu (menu_id),
    INDEX idx_type (op_type),
    INDEX idx_state (state)
);
```

### 3.3 角色-操作关联

```sql
CREATE TABLE org_role_operation (
    id              BIGINT PRIMARY KEY,
    role_id         BIGINT NOT NULL COMMENT '角色ID',
    operation_id    BIGINT NOT NULL COMMENT '操作ID',
    UNIQUE KEY uk_role_op (role_id, operation_id)
);
```

## 四、关联关系

### 4.1 实体关系图

```
┌─────────────────────────────────────────────────────────────────────────┐
│                              sys_menu                                    │
│  纯前端导航树，不承载权限语义                                             │
│  id, parent_id, title, path, route_name, component, icon, sort         │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    │ 1:N
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                           sys_operation                                  │
│  统一操作表：按钮 + API 合一                                              │
│  id, op_type, menu_id, op_name, perm_code, icon, sort                  │
│  api_path, api_method, auto_scan, state                                 │
│                                                                         │
│  ├─ op_type=1 按钮：menu_id 必填，api_path/api_method 为空             │
│  └─ op_type=2 API：menu_id 可选（为 NULL 表示独立API）                 │
│                    api_path/api_method 必填                             │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    │ perm_code = 权限码桥梁
                                    │
                    ┌───────────────┴───────────────┐
                    │                               │
                    ▼                               ▼
          ┌──────────────┐                  ┌──────────────┐
          │ org_role_    │                  │  前端鉴权     │
          │ operation    │                  │  buttons[]   │
          └──────────────┘                  └──────────────┘
```

### 4.2 关联规则

| 关系                   | 类型  | 说明                                                                         |
|----------------------|-----|----------------------------------------------------------------------------|
| **Menu → Operation** | 1:N | 强关联，操作天然属于某个菜单页面                                                           |
| **按钮 ↔ API**         | 松耦合 | `op_type=1` 的按钮和 `op_type=2` 的 API 通过 **`perm_code` 相等** 绑定。支持一个按钮对应多个 API |
| **Role → Operation** | N:M | 角色授权时勾选 `operation_id`。同一 `perm_code` 的按钮和 API 都会被授权                       |

### 4.3 数据示例

**sys_menu：**

| id | parent_id | title | path         | route_name  | component        | icon    | sort |
|----|-----------|-------|--------------|-------------|------------------|---------|------|
| 1  | 0         | 系统管理  | /manage      | -           | -                | setting | 1    |
| 11 | 1         | 用户管理  | /manage/user | manage_user | view.manage.user | user    | 1    |
| 12 | 1         | 角色管理  | /manage/role | manage_role | view.manage.role | role    | 2    |

**sys_operation：**

| id  | op_type | menu_id | op_name | perm_code   | api_path         | api_method | auto_scan |
|-----|---------|---------|---------|-------------|------------------|------------|-----------|
| 111 | 1       | 11      | 新增用户    | user:create | NULL             | NULL       | 0         |
| 112 | 1       | 11      | 编辑用户    | user:update | NULL             | NULL       | 0         |
| 113 | 1       | 11      | 导入用户    | user:import | NULL             | NULL       | 0         |
| 114 | 2       | 11      | 创建用户    | user:create | /api/user        | POST       | 1         |
| 115 | 2       | 11      | 修改用户    | user:update | /api/user/{id}   | PUT        | 1         |
| 116 | 2       | 11      | 上传文件    | user:import | /api/user/import | POST       | 1         |
| 117 | 2       | 11      | 解析模板    | user:import | /api/user/parse  | POST       | 1         |
| 118 | 2       | 11      | 批量保存    | user:import | /api/user/batch  | POST       | 1         |
| 201 | 2       | NULL    | 触发定时任务  | job:trigger | /api/job/trigger | POST       | 1         |

**说明：**

- `111` 是按钮，显示在"用户管理"页面
- `114` 是 API，和按钮 `111` 共享 `perm_code = user:create`
- 给角色授权 `operation_id = 111` 时，前端显示"新增用户"按钮
- 给角色授权 `operation_id = 114` 时，后端允许 `POST /api/user`
- 实际授权时角色勾选 `111` 和 `114`（或前端批量勾选同 perm_code 的按钮和 API）
- `113`"导入用户"按钮 和 `116/117/118` 三个 API 共享 `perm_code = user:import`，实现一个按钮对应多个 API
- `201` 是无菜单的独立 API，可用于后续扩展

## 五、后端接口设计

### 5.1 路由接口

| 接口                         | 方法  | 说明                                              |
|----------------------------|-----|-------------------------------------------------|
| `/route/getUserRoutes`     | GET | 查询当前用户有权限的菜单树，返回 `ElegantConstRoute[]` + `home` |
| `/route/getConstantRoutes` | GET | 返回公共路由（登录页、404 等）                               |

### 5.2 菜单管理接口

| 接口               | 方法              | 说明      |
|------------------|-----------------|---------|
| `/menu`          | POST/PUT/DELETE | 菜单 CRUD |
| `/menu/tree`     | GET             | 菜单树（全部） |
| `/menu/{menuId}` | GET             | 菜单详情    |

### 5.3 操作权限接口

| 接口                         | 方法              | 说明                                                                                                    |
|----------------------------|-----------------|-------------------------------------------------------------------------------------------------------|
| `/operation`               | POST/PUT/DELETE | 操作 CRUD                                                                                               |
| `/operation/page`          | GET             | 操作分页列表                                                                                                |
| `/operation/tree`          | GET             | 按菜单维度组织的操作树（菜单 + 其下的按钮 + API）                                                                         |
| `/operation/menu/{menuId}` | GET             | 指定菜单下的所有操作                                                                                            |
| `/operation/scan`          | POST            | **自动扫描**：扫描所有 Controller 的 `@Tag`/`@Operation`，将未记录的 API 自动写入 `sys_operation`（op_type=2, auto_scan=1） |
| `/operation/bind`          | POST            | 手动绑定：将按钮（op_type=1）和 API（op_type=2）通过 `perm_code` 关联                                                  |
| `/operation/unbind`        | POST            | 解除绑定                                                                                                  |

### 5.4 角色权限接口

| 接口                             | 方法  | 说明                              |
|--------------------------------|-----|---------------------------------|
| `/role/{roleId}/operations`    | GET | 获取角色已授权的操作列表                    |
| `/role/{roleId}/operation-ids` | GET | 获取角色已勾选的 operation_id 列表（前端回显用） |
| `/role/{roleId}/operations`    | PUT | 保存角色的操作权限（传入 operation_id 数组）   |
| `/role/{roleId}/menu-tree`     | GET | 获取角色有权限的菜单树（含按钮/API）            |

### 5.5 用户接口增强

| 接口           | 方法  | 说明                                                                                                                               |
|--------------|-----|----------------------------------------------------------------------------------------------------------------------------------|
| `/user/info` | GET | 返回 `{userId, userName, roles, buttons[], operations[]}`。`buttons` 为 `op_type=1` 的 `perm_code` 列表；`operations` 为全部 `perm_code` 列表 |

## 六、鉴权流程

### 6.1 系统用户

```
┌─────────────┐     ┌──────────────┐     ┌─────────────────────┐
│   前端登录   │────►│  carlos-auth │────►│ JWT Token           │
│             │     │              │     │ {user_id, role_ids, │
└─────────────┘     └──────────────┘     │  tenant_id}         │
                                         └─────────────────────┘
                                                    │
                              ┌─────────────────────┘
                              ▼
                    ┌─────────────────────┐
                    │   carlos-gateway    │◄── Caffeine 缓存
                    │ OAuth2Authorization │    用户权限（5分钟）
                    │      Filter         │
                    └─────────────────────┘
                              │
                              ▼
                    ┌─────────────────────┐
                    │   下游微服务         │
                    │ UserContextAuthFilter│
                    │  解析 X-User-* Header│
                    └─────────────────────┘
                              │
                              ▼
                    ┌─────────────────────┐
                    │ @PreAuthorize       │
                    │ hasPermission('user',│
                    │   'create')         │
                    └─────────────────────┘
                              │
                              ▼
                    ┌─────────────────────┐
                    │ PermissionService   │◄── Redis + Caffeine
                    │ getUserPermissions()│    多级缓存
                    └─────────────────────┘
```

**关键优化：**

1. **JWT Token 精简**：Token 只带 `user_id` + `role_ids`，不带完整权限列表
2. **缓存预热**：用户登录时，异步将 `role_id → perm_code` 写入 Redis
3. **权限变更同步**：修改角色权限后，Pub/Sub 通知所有节点清空 Caffeine 缓存

## 七、前端调整

### 7.1 动态路由对接

后端 `sys_menu` → `ElegantConstRoute` 转换：

| sys_menu 字段  | ElegantConstRoute 字段 |
|--------------|----------------------|
| `title`      | `meta.title`         |
| `path`       | `path`               |
| `route_name` | `name`               |
| `component`  | `component`          |
| `icon`       | `meta.icon`          |
| `hidden`     | `meta.hideInMenu`    |
| `sort`       | `meta.order`         |
| 子菜单          | `children` 递归        |

### 7.2 按钮权限

`getUserInfo` 返回：

```typescript
interface UserInfo {
  userId: string;
  userName: string;
  roles: string[];
  buttons: string[];      // op_type=1 的 perm_code 列表
  operations: string[];   // 全部 perm_code 列表（含 API）
}
```

前端控制：

```vue
<!-- 指令 -->
<button v-auth="'user:create'">新增用户</button>

<!-- 方法 -->
<button v-if="authStore.hasButton('user:create')">新增用户</button>
```

### 7.3 角色权限分配界面

统一为一颗权限树：

```
□ 系统管理 [菜单] ✓
│   □ 用户管理 [菜单] ✓
│   │   □ 新增用户 [按钮] ✓ ──► POST /api/user [API] ✓
│   │   □ 编辑用户 [按钮] ✓ ──► PUT /api/user/{id} [API] ✓
│   │   □ 导入用户 [按钮] ✓ ──► POST /api/user/import [API] ✓
│   │                               POST /api/user/parse [API] ✓
│   │                               POST /api/user/batch [API] ✓
│   □ 角色管理 [菜单] ✓
│       □ 新增角色 [按钮] ✓

□ 独立接口
      □ 触发定时任务 [API] ──► POST /api/job/trigger
```

前端展示规则：

- 菜单节点：可勾选，勾选后自动勾选其下所有按钮和 API
- 按钮节点：可勾选，勾选按钮时提示是否同时勾选绑定的 API
- API 节点：可独立勾选
- 独立 API（menu_id 为 NULL）平铺展示在"独立接口"分组下

### 7.4 新增页面

| 页面     | 说明                                              |
|--------|-------------------------------------------------|
| 权限管理   | 展示 `sys_operation` 全部数据，支持按菜单筛选、按 op_type 筛选    |
| API 扫描 | 点击"自动扫描"，调用 `/operation/scan`，展示新发现的 API，支持批量入库 |

## 八、实施步骤

### Phase 1: 数据库重构

1. 改造 `sys_menu`：字段保持不变，确保数据完整
2. **新建 `sys_operation` 表**（`sys_menu_operate` 的数据迁移到此，增加 op_type/api_path/api_method/auto_scan 字段）
3. **删除 `sys_resource` 表和 `sys_resource_category` 表**
4. 新建 `org_role_operation` 表（替代 `org_role_permission` 或并行存在，按需）

### Phase 2: 后端改造

1. 删除 `system.resource` 模块全部代码（`SysResource`、`SysResourceCategory`、Controller、Service、Manager、Mapper、XML）
2. 改造 `system.menu` 模块：
    - `Menu` 保留
    - `MenuOperate` 改造为 `SysOperation`，增加字段，改名
    - `MenuOperateController` 改造为 `SysOperationController`
    - `MenuOperateService` 改造为 `SysOperationService`
3. 实现 `ResourceStore` 新实现：扫描结果写入 `sys_operation`（op_type=2, auto_scan=1）
4. 实现 `/operation/scan` 自动扫描接口
5. 实现 `/route/getUserRoutes`：从 `sys_menu` 构建路由
6. 增强 `/user/info`：返回 `buttons` 和 `operations`
7. 实现角色权限分配接口

### Phase 3: 前端改造

1. 菜单管理页面：对接 `sys_menu` 接口
2. 权限管理页面：新增，展示 `sys_operation`，支持按菜单/类型筛选
3. API 扫描页面：调用 `/operation/scan`，展示扫描结果，批量入库
4. 角色权限分配：合并 menu-auth-modal + button-auth-modal，统一权限树
5. 实现 `v-auth` 指令
6. 动态路由：`initDynamicAuthRoute` 对接 `/route/getUserRoutes`
