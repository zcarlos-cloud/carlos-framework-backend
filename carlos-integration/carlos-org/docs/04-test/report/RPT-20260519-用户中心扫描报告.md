## 6. 核心代码问题摘要

### 6.1 Service 层大TODO Stub

`OrgUserService.java:264-399` 存在 7 个空实现方法，仅打印日志，未操作关联表：

- `importUser()` 空实
- `exportUser()` 空实
- `assignDepartments()` 仅更新主部门 ID
- `assignRoles()` 空实
- `assignPositions()` 空实
- `getUserDepartments()` 返回空列
- `getUserRoles()` 返回空列
- `getUserPositions()` 返回空列

### 6.2 密码复杂度校验不完整

```java
// OrgUserService.java:409-414
private boolean checkPasswordComplexity(String password) {
    if (StrUtil.isBlank(password) || password.length() < 8) {
        return false;
    }
    return true;  // 未校验大小写、数字、特殊字符组
}
```

需求要求：至少8位，包含大小写字母、数字、特殊字符中的至种

### 6.3 删除部门无约束校

需求要部门下有子部门或用户时不允许删除"，当`OrgDepartmentService` 的删除逻辑未校验子部门或关联用户，直接执行删除

### 6.4 用户删除未级联清理关联数

用户逻辑删除后，以下关联表中的数据未清理

- `org_user_department`
- `org_user_role`
- `org_user_position`

### 6.5 审计日志表未创建

需求文档定义了以下审计相关表，SQL 脚本中不存在

- `org_operation_log` 操作日志 (亿级，需归档)
- `org_login_log` 登录日志 (亿级，需归档)
- `org_audit_record` 审计记录
