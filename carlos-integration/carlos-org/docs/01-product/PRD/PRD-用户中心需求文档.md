## 1. 文档概述

### 1.1 目的

本文档详细定义Carlos Framework 用户中心模块的功能需求、业务规则、接口规范及非功能性需求，为开发团队提供清晰的技术实现指导。

### 1.2 适用范围

本文档适用于用户中心模块（carlos-org）的设计、开发、测试及维护人员。

### 1.3 术语定义

| 术语   | 定义                              |
|------|---------------------------------|
| 租户   | 系统多租户隔离的基本单位，不同租户数据完全隔。         |
| 职系   | 岗位类别，如管理系(M)、技术系(T)、专业系(P)否     |
| 职级   | 同一职系内的等级划分，如 T1、T2-1、M3 等       |
| 主部门  | 用户的主要归属部门，一个用户只有一个主部门           |
| 主岗位  | 用户的主要任职岗位，一个用户可有多个岗位但只有一个主岗位    |
| 数据权限 | 角色可查看的数据范围：全部/本部门及子部门/仅本部门/仅本人/自定义 |

## 3. 功能需。

### 3.1 用户管理模块

#### 3.1.1 用户基本信息管理

**功能描述:**
管理企业员工的账号信息，包括账号创建、编辑、禁用、启用、删除等操作。

**核心字段:**

| 字段。             | 类型           | 必填 | 说明               |
|-----------------|--------------|----|------------------|
| id              | BIGINT       | 否  | 主键，雪花ID          |
| account         | VARCHAR(20)  | 否  | 用户名，租户内唯一        |
| nickname        | VARCHAR(20)  | 否  | 昵称/真实姓名          |
| pwd             | VARCHAR(64)  | 否  | 密码，SM2加密存储       |
| identify        | VARCHAR(18)  | 否  | 证件号码（身份证。        |
| phone           | VARCHAR(11)  | 否  | 手机。              |
| email           | VARCHAR(30)  | 否  | 邮箱               |
| gender          | TINYINT      | 否  | 性别。保密, 1否 2否     |
| avatar          | VARCHAR(200) | 否  | 头像URL            |
| state           | TINYINT      | 否  | 状态：0禁用, 1启用, 2锁定 |
| main_dept_id    | BIGINT       | 否  | 主部门ID            |
| login_time      | DATETIME     | 否  | 最后登录时间           |
| login_ip        | VARCHAR(50)  | 否  | 最后登录IP           |
| login_count     | INT          | 否  | 登录次数             |
| pwd_last_modify | DATETIME     | 否  | 密码最后修改时。         |

**业务规则:**

1. **账号唯一。*: 用户名在同一租户内必须唯一
2. **密码安全**:
    - 密码必须包含大小写字母、数字、特殊字符中的至少
    - 密码长度不少于8位
    - 使用SM2国密算法加密存储
    - 默认90天必须修改密。
3. **状态流。*:
    - 启用、禁用、启用
    - 启用、锁定（连续5次密码错误）。启用（管理员解锁。0分钟后自动解锁）
4. **主部门约。*: 用户必须有且只有一个主部门
5. **逻辑删除**: 删除操作为逻辑删除，保留历史数。

**功能清单:**

| 功能编号   | 功能名称    | 功能描述           | 优先。 |
|--------|---------|----------------|-----|
| UM-001 | 用户列表查询  | 支持分页、条件筛选、模糊搜索 | P0  |
| UM-002 | 用户详情查询  | 查询用户完整信息及关联关。  | P0  |
| UM-003 | 新增用户    | 创建用户账号，支持批量导入  | P0  |
| UM-004 | 编辑用户    | 修改用户基本信息       | P0  |
| UM-005 | 删除用户    | 逻辑删除用户         | P0  |
| UM-006 | 启用/禁用用户 | 切换用户状态         | P0  |
| UM-007 | 解锁用户    | 管理员解锁被锁定的账。    | P1  |
| UM-008 | 重置密码    | 管理员重置用户密码      | P0  |
| UM-009 | 修改密码    | 用户自主修改密码       | P0  |
| UM-010 | 用户导入    | Excel批量导入用户    | P1  |
| UM-011 | 用户导出    | 导出用户列表到Excel   | P1  |
| UM-012 | 用户分配部门  | 设置用户主部门及兼职部门   | P0  |
| UM-013 | 用户分配角色  | 为用户分配角。        | P0  |
| UM-014 | 用户分配岗位  | 设置用户主岗位及兼岗     | P1  |

#### 3.1.2 用户导入功能

**功能描述:**
通过Excel批量导入用户数据，支持模板下载、数据校验、错误反馈。

**导入字段:**

| 字段。      | 必填 | 校验规则              |
|----------|----|-------------------|
| account  | 否  | 用户名，租户内唯一。-20字符   |
| realname | 否  | 真实姓名。-20字符        |
| identify | 否  | 身份证号。8位，校验格式      |
| phone    | 否  | 手机号，11位数。         |
| role     | 否  | 角色名称，需存在          |
| dept     | 否  | 部门路径，如"总部-技术部-研发。 |
| gender   | 否  | 性别：男/女保密          |
| email    | 否  | 邮箱格式校验            |

**导入流程:**

```
1. 下载导入模板
       │
       │
2. 填写数据并上传Excel
       │
       │
3. 系统校验数据格式
   ├─ 格式错误 │返回错误报告
   └─ 校验通过，继续
       │
       │
4. 数据唯一性校验（账号、手机号
   ├─ 重复，标记冲突，支持覆。跳过
   └─ 通过，继续
       │
       │
5. 关联数据校验（部门、角色）
   ├─ 不存。│标记错误
   └─ 存在，继续
       │
       │
6. 预览导入结果
       │
       │
7. 确认导入、批量写入数据库
       │
       │
8. 发送通知（邮。短信）给新用。
```

### 3.2 部门管理模块

#### 3.2.1 部门组织架构

**功能描述:**
管理企业组织架构，支持多级部门、部门树展示、部门合并与拆分批

**核心字段:**

| 字段。       | 类型           | 必填 | 说明               |
|-----------|--------------|----|------------------|
| id        | BIGINT       | 否  | 主键               |
| parent_id | BIGINT       | 否  | 父部门ID不为根部门       |
| dept_name | VARCHAR(64)  | 否  | 部门名称             |
| dept_code | VARCHAR(64)  | 否  | 部门编号，唯一          |
| path      | VARCHAR(500) | 否  | 部门路径，如"/1/5/23/" |
| leader_id | BIGINT       | 否  | 负责人ID            |
| state     | TINYINT      | 否  | 状态：0禁用, 1启用      |
| sort      | TINYINT      | 否  | 同级排序             |
| level     | INT          | 否  | 层级深度             |

**业务规则:**

1. **层级限制**: 部门层级最多支持0个
2. **唯一。*: 部门编号在同一租户内唯一
3. **删除约束**: 部门下有子部门或用户时，不允许删。
4. **path维护**: 部门移动时自动更新所有子部门的path
5. **负责。*: 部门负责人必须是该部门或其子部门的成。

**功能清单:**

| 功能编号   | 功能名称    | 功能描述        | 优先。 |
|--------|---------|-------------|-----|
| DM-001 | 部门树查。   | 查询完整部门树结。   | P0  |
| DM-002 | 部门列表    | 平铺列表展示，支持筛。 | P0  |
| DM-003 | 新增部门    | 创建新部。       | P0  |
| DM-004 | 编辑部门    | 修改部门信息      | P0  |
| DM-005 | 删除部门    | 删除空部。       | P0  |
| DM-006 | 移动部门    | 调整部门层级      | P1  |
| DM-007 | 部门排序    | 调整同级部门顺序    | P1  |
| DM-008 | 部门人员列表  | 查看部门下的用户    | P0  |
| DM-009 | 设置部门负责。 | 指定部门负责。     | P1  |
| DM-010 | 部门角色配置  | 设置部门默认角色    | P2  |

#### 3.2.2 部门编制管理

**功能描述:**
管理各部门的人员编制，包括编制数设置、在编统计、超编预警

**业务规则:**

1. **编制类型**: 标准岗有编制限制，虚拟岗/兼职岗无编制限制
2. **编制统计**: 实时计算各岗位的在编人数和空缺人。
3. **超编预警**: 在编人数超过编制数时发出预警
4. **编制冻结**: 部门可设置冻结编制，暂停招聘

#### 3.3.2 权限管理

> **v1.1.0 修订（ADR-003)**: 权限资源定义已收归 carlos-system（菜单 `sys_menu`、操作权限 `sys_operation`:按钮+API 两类）,
> carlos-org 不建设 `org_permission` 表，仅持有角色-操作授权关联 `org_role_operation`。
> 原"数据字段"级权限类型不落地，敏感字段脱敏由框架 translation/encrypt 能力与 VO 层承担。
> 已知缺口：动态路由模式下菜单可见性不受角色控制（`sys_menu.meta.roles` 为死字段），为后续专项。

**功能描述:**
为角色配置可执行的操作权限（按钮/API)，权限资源本身由 carlos-system 维护。

**授权关联字段（org_role_operation):**

| 字段          | 类型     | 必填 | 说明                       |
|-------------|--------|----|--------------------------|
| id          | BIGINT | 是  | 主键                       |
| role_id     | BIGINT | 是  | 角色ID                     |
| operation_id | BIGINT | 是  | 操作ID，引用 carlos-system `sys_operation.id` |
| tenant_id   | BIGINT | 否  | 租户ID                     |

**业务规则:**

1. 授权写入时校验 `operation_id` 在 `sys_operation` 中存在（应用层校验，跨模块无数据库外键）
2. 同一角色对同一操作不可重复授权（唯一索引 `uk_org_role_operation`)
3. 角色数据范围（data_scope）与操作授权正交：前者管"看哪些数据"，后者管"能做哪些操作"

**功能清单:**

| 功能编号   | 功能名称    | 功能描述           | 优先级 |
|--------|---------|----------------|-----|
| PM-001 | 权限树查询   | 查询权限树（数据源 carlos-system) | P0  |
| PM-007 | 配置角色权限  | 为角色分配按钮/API 权限（org_role_operation) | P0  |
| PM-008 | 配置数据权限  | 设置角色数据范围（org_role.data_scope) | P0  |

### 6.2 索引策略

- **主键索引**: 所有表使用雪花ID作为主键
- **唯一索引**: 用户名、部门编号、角色编码等需要唯一约束的字。
- **组合索引**: 常用于查询条件的字段组合，如租户ID+状。时间
- **全文索引**: 用户姓名、部门名称等需要模糊搜索的字段
