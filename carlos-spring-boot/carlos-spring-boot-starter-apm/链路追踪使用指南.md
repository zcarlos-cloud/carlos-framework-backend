# Carlos Framework 链路追踪使用指南

## 快速开始

### 1. 引入依赖

下游微服务只需引入一个模块：

```xml
<dependency>
    <groupId>com.carlos</groupId>
    <artifactId>carlos-spring-boot-starter-apm</artifactId>
</dependency>
```

**需要显式开启总开关**——在 `application.yml` 中加入：

```yaml
carlos:
  apm:
    enabled: true
```

开启后 `MdcFilter` 自动从请求头提取 traceId 写入日志 MDC，`mdc` / `tracing` / `feign`
三组子开关默认都是 `true`，无需逐一配置。

> `carlos.apm.enabled` 默认 `false`。只引入依赖而不开总开关时，本模块的所有 Bean 都不会装配，
> 日志中的 `%X{traceId}` 会一直为空。

### 2. 配置日志格式

将 `logback-spring.xml` 的输出格式设为包含 `%X{traceId}` 和 `%X{spanId}`：

```xml
<property name="LOG_PATTERN"
    value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level [%X{traceId:-}-%X{spanId:-}] %logger{36} - %msg%n"/>
```

日志输出效果：

```
2026-06-16 14:30:25.123 [http-nio-8080-exec-1] INFO  [4bf92f3577b34da6-00f067aa0ba902b7] c.c.s.controller.UserController - 查询用户成功
```

### 3. 人工追踪

```bash
# 从响应头获取 Trace ID
curl -v http://localhost:8080/api/user/list
# < X-Trace-ID: 4bf92f3577b34da6

# grep 串起全链路日志
grep "4bf92f3577b34da6" logs/*.log
```

## API 参考

### TraceUtil（推荐入口）

获取追踪 ID：

```java
import com.carlos.apm.TraceUtil;

// 获取 Trace ID（分层优先级：SkyWalking → Brave → MDC）
String traceId = TraceUtil.getTraceId();

// 获取 Span ID
String spanId = TraceUtil.getSpanId();

// 检查是否在追踪上下文中
if (TraceUtil.isInTraceContext()) {
    log.info("请求被追踪, Trace ID: {}", TraceUtil.getTraceId());
}
```

添加上下文标签：

```java
// 为当前 Span 添加业务标签（Agent 存在时写入 SkyWalking，否则写入 Brave）
TraceUtil.tag("user.id", userId);
TraceUtil.tag("order.no", orderNo);
```

记录错误：

```java
try {
    // 业务逻辑
} catch (Exception e) {
    TraceUtil.recordError(e);  // 自动适配 SkyWalking / Brave
    throw e;
}
```

方法级追踪（注解方式）：

```java
@TraceTag(key = "order.create", value = "#order.id")
public Order createOrder(OrderCreateParam param) {
    // 该方法耗时、入参、出参自动记录
}
```

调试用上下文信息：

```java
// 返回格式化的追踪上下文（含 traceId + spanId ± swSegmentId）
log.debug("追踪上下文: {}", TraceUtil.getTraceInfo());
```

### MdcUtil（日志上下文）

```java
import com.carlos.apm.mdc.MdcUtil;

// 获取 MDC 中的追踪值
String traceId = MdcUtil.getTraceId();
String spanId = MdcUtil.getSpanId();

// 设置自定义 MDC 值（如需临时业务标签）
MdcUtil.put("businessKey", orderNo);
MdcUtil.remove("businessKey");
```

## 追踪配置

### 完整配置参考

```yaml
carlos:
  apm:
    # 总开关
    enabled: true

    # Layer 1: MDC 日志上下文
    mdc:
      enabled: true                # 是否启用 MDC
      trace-id-key: traceId        # MDC 中 traceId 的 key
      span-id-key: spanId          # MDC 中 spanId 的 key
      add-to-response: true        # 响应头返回 X-Trace-ID
      response-header-name: X-Trace-ID  # 响应头名称

    # Layer 2: Brave 链路追踪
    tracing:
      enabled: true                # 是否启用链路追踪
      sample-rate: 1.0             # 采样率（0.0=不采样，1.0=全采样）
      propagation: B3_SINGLE       # B3_SINGLE（单头，推荐）或 B3_MULTI（多头，兼容旧版）

    # Layer 3: SkyWalking 增强
    skywalking:
      enabled: AUTO                # AUTO=自动检测 / true=强制 / false=禁用
      takeover: true               # Agent 存在时是否接管 Trace ID
      enrich-log: true             # 是否在 MDC 中写入 tid（SkyWalking Trace ID）

    # Feign 传播
    feign:
      enabled: true                # 是否自动向 Feign 请求注入 B3 头
```

### 环境配置示例

**开发环境（全采样）**：

```yaml
carlos:
  apm:
    tracing:
      sample-rate: 1.0
```

**生产环境（采样 10%）**：

```yaml
carlos:
  apm:
    tracing:
      sample-rate: 0.1
```

## 跨服务追踪验证

### 验证链路完整性

```bash
# 1. 发起请求，获取 Trace ID
curl -v http://gateway:8080/api/user/info
# < X-Trace-ID: abc123def456

# 2. 在各服务日志中 grep
grep "abc123def456" gateway/logs/*.log
grep "abc123def456" system-service/logs/*.log
grep "abc123def456" org-service/logs/*.log

# 3. 确认 traceId 在各服务中一致
```

### 验证 Feign 传播

```java
// 在 Feign 调用方日志中确认
@Slf4j
@Component
public class OrderClient {
    public void query() {
        log.info("调用订单服务, traceId: {}", TraceUtil.getTraceId());
        // Feign 调用自动携带 B3 头
        orderApi.queryOrder(orderId);
    }
}

// 在被调用方日志中确认 traceId 一致
```

## SkyWalking 集成

### 部署 Agent

```bash
# 下载 Agent
wget https://archive.apache.org/dist/skywalking/java-agent/9.5.0/apache-skywalking-java-agent-9.5.0.tgz
tar -xzf apache-skywalking-java-agent-9.5.0.tgz

# 启动服务（加入 -javaagent 参数）
java \
  -javaagent:./skywalking-agent/skywalking-agent.jar \
  -DSW_AGENT_NAME=carlos-system-service \
  -DSW_AGENT_COLLECTOR_BACKEND_SERVICES=oap-server:11800 \
  -jar carlos-system-service.jar
```

### Agent 部署后自动行为

| 行为          | Agent 部署前 | Agent 部署后        |
|-------------|-----------|------------------|
| Trace ID 来源 | Brave     | SkyWalking（自动切换） |
| Span 上报     | 无         | 自动上报 OAP Server  |
| 可视化         | grep 日志   | SkyWalking UI    |
| 服务拓扑        | 无         | 自动生成             |
| 代码改动        | —         | **零改动**          |

## 常见问题

### Q: 日志中没有 traceId 输出？

确认：

1. 引入了 `carlos-spring-boot-starter-apm` 依赖
2. `carlos.apm.enabled` 为 `true`（**默认 false，必须显式开启**）
3. `carlos.apm.mdc.enabled` 为 `true`（默认）
4. logback 格式包含了 `%X{traceId}`

### Q: 跨服务 traceId 不一致？

确认：

1. Gateway 的 `carlos.gateway.tracing.enabled` 为 `true`
2. 下游服务的 `carlos.apm.tracing.enabled` 为 `true`
3. 请求链路上没有中间件（Nginx/LB）剥离 B3 头

### Q: 如何降低采样率？

```yaml
carlos:
  apm:
    tracing:
      sample-rate: 0.1   # 10% 采样
```

未采样的请求：MDC 中仍有 traceId（Layer 1 兜底），但 Brave 不创建 Span。

### Q: 前端如何获取 Trace ID？

响应头中返回 `X-Trace-ID`，前端可直接读取：

```javascript
const response = await fetch('/api/user/info');
const traceId = response.headers.get('X-Trace-ID');
console.log('Trace ID:', traceId);
// 用户报障时提供此 ID，后端即可 grep 定位
```
